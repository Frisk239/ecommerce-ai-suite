# 第四阶段 roadmap：体系完整化与真实使用（2026-09-16 立项）

日期：2026-09-16。来源：Owner grill 会话逐项签核。名词溯源：「懂王Ai 口径」=B 站 UP 主「懂王Ai」的电商 AI 体系主张（8 项目以数据中台为核心，2026-09-16 两期视频实测转写）；「Q1–Q10」=该 grill 会话十组裁决的编号，**裁决结论已全部落进本文件各刀，无需回查会话记录**。状态：**Owner 立项，施工权威**——第三阶段（`docs/roadmap-product-hardening.md`，41–48 刀）已收官并降级为存档。

## 北极星

**真实使用一次贯穿，懂王口径逐项可指代码，证据纪律不松反紧。**三条验收线：

1. **戏台完整**：懂王口径 8+1 项（AI 客服 / RAG 知识库 / 数据中台 / 多模态素材 / 直播切片 / 销售考核 / 微调数据供给 / MCP 架构 / 自媒体内容）每项有对应模块且可演示或可指文件——其中「微调数据供给」以**数据集导出**形态满足，产品仍不训练；「多模态素材」以**图片治理 + 媒体引用回答 + 直播洗帧的内容自循环**（94a/b/c）满足，**图生成仍 Out**。
2. **真实使用**：一个真实运营的数码外设「店」——开放数据集灌入 + 店主自写政策口径 + widget 挂公网静态页 + 真实问法 50+ 条 + 拒答飞轮真转一圈 + 直播源录像过 ASR→拣选→真切→客服拉切片全链路；产出使用日志与实测数字。
3. **证据纪律**：每刀 CI 全量绿；动检索/生成必 before/after 同报告（`docs/research/rag-eval-report.md`）；**数据灌入/订正类刀必重跑基线并逐位对账**（审计刀 15 机制约束）；工具语义变更必 ADR；真实使用问法回流评测集。

## 第二梯队：真实使用贯穿（92–96）

> 使用是持续动作不是单刀：checkpoint 1 在 92（文字线），checkpoint 2 在 96（直播线）。

### 第 92 刀：使用剧本第一轮（运营动作刀，代码改动≈0）

- 内容：治理全流程真实走（上传→机洗→人洗→发布）；真实问法 50+（正常问/口语改写/无证据故意问/多轮指代/转人工——同义词表外的自然用词重点采集）；拒答飞轮转一圈（缺口→补口径→发布→同问法再问命中）；评分+负反馈+回流登记；MCP 用外部客户端真连（Cursor 按现有 mcp.json）。

- 审计刀 18 排本刀后。

### 第 93 刀：ASR 刀（A 档升级，必开 ADR）

- 内容：`ASR_API_KEY`/`ASR_MODEL` env（选型依 89 刀定案）；云转写带句级时间戳→**停顿聚合成候选段**落 `clip_candidates`（pending，人工拣选闸门保留）；候选新增只读标注 `transcript_source: cloud|local|manual`；无 key=无自动转写（人工填字段兜底，fail-诚实）；本地兜底 `scripts/transcribe_local.py`（不进 api 镜像运行时依赖——CPU 转写超「同步 ≤20s」纪律；可选依赖组形态）；主轨自录录像过链路，转写准确率与候选质量实测数字进 closeout。
- 词条：**转写来源**（cloud/local/manual，只读，来源是既成事实）。
- 验收：一段真实录像从上传到候选落队的全自动转写实跑记录；话术纪律检查（closeout 无量级吹嘘词）。

### 第 94a 刀：图片资产活化 + 商品素材视图（必开 ADR）

- 内容：迁移给图片资产加**「图片描述」治理字段**（video.transcript 同构：人洗补写生效，描述切块进检索索引——图片从此可被命中）；`VLM_API_KEY/VLM_BASE_URL/VLM_MODEL` 独立 env——VLM 看图出**描述草稿**（人确认才生效，LLM 只出草稿不出事实；未配置=纯人洗补写兜底，fail-诚实）；**商品详情页加「素材」聚合段**——该商品关联的图/视频/文案素材卡（来源/版本/状态），素材库不建独立页（资产列表+来源筛选已存在），聚合做在商品维度；图片来源双轨：运营上传为主 + Pexels 辅轨拉产品展示图（Pexels 本以图库为主；89 刀 Pexels key 债一并清——视频辅轨用途仍按 89 刀定案留给录像线），**生图维持 Out**（goal §7 死守）。
- 词条候选：**图片描述**（人洗确认后生效的检索文本面）。
- 验收：上传商品图→补描述→发布→顾客问图片内容词命中该资产（e2e）；Pexels 辅轨图带许可落库。

### 第 94b 刀：媒体引用回答（必开 ADR）

- 内容：检索命中图片/视频类资产时 `complete` 载荷新增 `media_citations: [{asset_id, version_no, mime}]`——**服务端定，模型无决定权**（与 citations 同纪律）；媒体字节端点 `GET /api/customer/assets/{id}/media`（顾客令牌/操作者 cookie 鉴权、只出已发布指针版、图片直出/视频支持 Range；不暴露对象存储路径）；文本回答纪律不变（描述/transcript 证据照常组装/生成，拒答与覆盖闸照旧）；客服页与 widget 端渲染（图片直出、视频播放器）。
- 词条候选：**媒体引用**。
- 验收：命中切片的回答带可播附件、命中图片的回答带图；未发布/废弃版本媒体端点拒绝的钉测。

### 第 94c 刀：直播洗帧（必开 ADR）

- 内容：对已发布视频资产触发「洗帧到素材库」——VLM 按转写句时间戳定位候选帧（挑商品特写/清晰帧打分），每候选=时间点+对应转写句+帧预览；**人工拣选闸门**（与切片拣选同款交互，「自动候选+人工确认」模式第三次复用——ASR 候选/评论回流先例）；确认帧登记为独立图片资产（字节=该帧 jpg；新来源词 `clip_frame`），血缘可见「切自哪个视频资产」（与切片回执同追溯模式）；登记后走 94a 通用治理（VLM 描述草稿→人确认→进索引）→ 94b 可引用。**帧不是视频资产的版本，是独立资产**；全自动直接入库被否（发布权在人，对帧破例即破治理故事）。
- 验收：一段已发布切片洗出 ≥1 张商品帧→描述确认→顾客问商品图命中该帧资产。

### 第 95 刀：widget 轻量续接刀

- 内容：打开 widget 时本地存有未过期令牌且会话 active → 恢复该会话（消息重放+继续问）；已结束会话不复活（结束=关对话流不关善后，口径不变）。
- 验收：关页面重开续聊的端到端；过期令牌走新会话。

### 第 96 刀：使用剧本Ⅱ（直播线端到端）+ 体系闭环演示三层

- 内容（运营动作 + 演示支撑设施三层，2026-09-16 grill 增补）：自录源录像→上传→ASR 候选→人工拣选→ffmpeg 真切 mp4→发布→顾客问「这产品什么特点」**拉切片回答**→**洗帧出商品图进素材库→再被客服引用**——完整内容自循环链路实测，使用日志第二轮追加。
- **三层演示设施**（本刀 Must，定位=「我自己用用」的闭环支撑，非对外表演）：
  1. 《体系闭环演示手册》（`docs/demo-system-loop.md`）：按演进链顺序编排 12+ 回路（拒答飞轮/版本指针/三态治理/回流变知识/图片治理/内容自循环/MCP 读权威/降级诚实/OOV 分说/质检双闸/SFT 血缘/考核题源锚），每幕=操作步骤+预期画面+对应主张+可指测试文件——**手册分「已实现幕」与「在途幕」两栏**（SFT 血缘幕待 97、质检双闸幕待 98 落地后移入已实现栏，在途幕如实标注对应刀号）；
  2. `demo_prepare` 一键就绪态：在 demo_reset 清探针之上，把演示库带到「体系演示就绪」（数码店数据+演示图/录像就位+主线会话齐），任何时刻 5 分钟可开演；
  3. 端到端剧本测试：`test_system_loop` 级 e2e——拒答→补口径→再问命中→会话回流→机洗 QA→发布→新问法再命中，一次测试走完治理飞轮全环（兼作 92 使用剧本的机械验收器）。单环断言已大量存在于 1218 测试中，e2e 只补「串场」这一条，不翻倍测试矩阵。

- 内容：`scripts/eval/collect_questions.py`（会话表导出真实问法：去重+按分布预分类，人审后期望值手工定——机器不给自己出题打分）；golden 96→**~200**（正例 ~80/同义 ~60/混淆 ~25/应拒答 ~30，比例保持）；新增第五分布**表外同义探针**（真实问法中同义词表之外的自然改写 10–20 条——第 36 刀「无有效探针」就此补上）；基线刷新；**embedding 评估门执行**：若同义/表外探针组 recall@1 < 70%，向量/rerank 增强立项（before/after 同报告）；否则「词法足够」结论+数字存档 rag-eval-report——**两个结果都是可讲证据**。
- 词条：**表外同义探针**。
- 验收：200 条四+一分布全量数字入档；评估门结论段落；不追 500 条（基线漂移对账成本会反噬可信度，Q9）。

### 第 102 刀：生成路径忠实度观察刀

- 内容：`run_eval.py --judge-llm` 对真实使用攒下的 LLM 生成回答跑 judge（口径沿用 87 刀：两遍一致+标注跑全日期）；一次性观察报告进 rag-eval-report 附录；**不进 CI**（非确定性不进可复现尺）。
- 验收：报告含生成路径 judge 数字与口径边界声明；面试答「生成路径也有数字」成立。

### 第 103 刀：压测刀

- 内容：locust 脚本压三路径（SSE 生成/拒答词法/工具查询）+ /health；**在服务器真环境跑**；`docs/research/perf-report.md`（TTFT 分位、RPS、错误率、限流闸触发行为验证）——`ttft_seconds` 埋点终于有报告数字。
- 验收：报告入档；限流闸在压测下按 429+Retry-After 预期触发。
