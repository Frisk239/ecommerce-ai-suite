## 一、这不是什么

- 不是落地页/深色模式/动效升级。产品是商家侧操作台（VARIANCE 2 · MOTION 1 · DENSITY 7）。
- 不是重做七块能力。①④ 的治理与客服工作区骨架可留；薄的是脏数据、引用核验、缺口补洞、顾客停答、磁贴回潮。
- 不是删掉真实灌入。Wikidata / OFF / WANDS 是第 32–33 刀的数据主线，列表默认「工作队列」即可，不整包删除。
- 不是新开模型配置页。工程已锁「知识变好靠发布，不靠训练」（ADR 0028）；原型 `/models` 不复活，除非 Owner 另开刀。
- 不替代第 43 刀仪表。43 加趋势和角标；本方案先拆掉总览/资产页上重复的等宽统计卡，避免 43 再叠第六张磁贴。

## 二、诊断（2026-09-10 浏览器实证）

廉价感不是「缺渐变」，是三件事叠在一起：

1. **工作台被测试/灌入数据淹了。** 资产默认「全部」261 条（复核口径：全部 261 / 待人洗 206 / 已发布 55）：`mcp-smoke 保温杯` ×12 与 `evidence probe evidence-unpublished-…` ×4 共 16 条连成片（id 246–259），全属待人洗、来源 `source_kind='mcp_registered'`；`未命名资产` 是 4 条 NULL 标题（id 13/260–262）经前端兜底渲染，且都已发布。商品页保温杯旁边是 `Trifolding phone` / `Malyutka` / `Panavision 3D`（均未定价；全库 115 件仅 3 件已定价）。客服问「你们卖什么」打印 115 件里的前 20 件（`MAX_LISTED=20`，`catalog_tools.py:38`）——其中 18 件「价格未定」。切片混 `WANDS 家具（演示）`（34 条候选里 30 条）。考核题库混英文问句（来源是 ABCD/ASAPP MIT，非 Bitext——全仓无 Bitext）。
2. **产品故事的核（引用可核验）没落地。** 点 `A-0029 · v1`（客服刚用来答退货运费）落到「衣服评论 · 发货速度慢的死…」；主栏无原文（`TranscriptPanel` 只给 `kind=dialogue`，`AssetDetailPage.tsx:1032`）；`?v=N` 不改变主栏内容，只高亮版本列表（`AssetDetailPage.tsx:635-648`）；主按钮是「开修订」。蓝字「引用回放锚定」不是只读证据视图。对照 UX-NOTES §二.7 与 ADR 0007。**（复核：`api.getVersionText` 已存在且对 document 同样可用——后端 `GET /assets/{id}/versions/{n}/text` 走对象存储字节，实测 asset 29 v1、asset 13 v3 均取回正文；见 §九。）**
3. **v3 扁平语言被加回仪表盘套件。** 画布/面板/主钮渐变、hover 上浮、总览五张等宽卡、资产 tab 再叠三张同样数字的卡、商品空卡片、切片假视频框、发送钮 34px 蓝圆。页头 3–5 行 ADR 说明书。390：tab 溢出、统计卡吃掉首屏、表格 `nowrap` 只露半列。

交互上，操作者每天会踩空的路径：

| 路径 | 现状 | 应是 |
| --- | --- | --- |
| 引用芯片 `?v=N` | 进可编辑工作版本，文档类不见正文 | 只读快照：横幅 + 该版原文 + 禁止人洗；编辑走待人洗版本 |
| 缺口「去补文档」 | 问句进预填标题（抽屉头是「补缺口 G-xxxx」，`RegisterAssetDrawer.tsx:263`）、后端无 `session_id` 字段（表里就没有）、拒答路径商品恒空（`knowledge_gaps.py:70-72`） | 抽屉带问句/会话/商品（**需后端加缺口来源会话字段**）；目录意图不进缺口；tab 计数=列表口径 |
| 顾客通道流式 | 无 Stop/Esc；卸载不 abort | 与 `/service` 同一状态机 |
| 待人洗队列 | 无搜索/分页，默认「全部」 | 默认待人洗；工作队列 vs 含测试 |
| 客服会话列表 | 大量「进行中 ·（还没有提问）」 | 空会话不占进行中；顾客/预览可扫 |
| 两种「发布」 | 投放也是近黑主钮 | 治理发布=主钮；投放=次钮+说明 |
| 不可逆动作 | 回流有确认；切片拣选/素材抽检通过无确认；废弃后停在详情 | 同一套确认+后果文案；废弃回列表 |
| 窄屏 | 侧栏变抽屉，表仍是表 | 资产/缺口关键表 → 卡片 |

做得对、本方案不翻案：发布闸门分缺项 vs 待确认、拒答/转人工徽章、工具条 vs 引用芯片分色、操作者客服 Stop/Esc、登录深链、404 不回总览、商品抽屉「规格只读写回、价格直写」。

## 三、原则（开刀时对照，禁止另起炉灶）

**做**

- 色彩只承担语义。主按钮近黑 `#0F1115`；蓝 `#4176E6` 只给链接、选中左标、引用芯片、focus、顾客气泡。
- 海拔 = 1px 墨线。禁止面板/画布/按钮的装饰性纵向渐变和 hover `translateY`。
- 列表页 = 分段 + 密度表，不是等宽卡网格。数字重复出现一次即可（tab 或摘要条，二选一）。
- 页头：标题 + 最多一句职责。ADR 编号、枚举名、实现注释不进界面。
- 每个主动作写明后果。禁用必须写缺什么。空态写怎么不空。
- 引用验证成本以秒计：点芯片 → 看见该版正文。
- 验收：改过的路径 1280 与 390 都要点穿，e2e 绿 ≠ 验收。

**不做**

- 深色模式、紫粉渐变、三列功能卡、假视频/假仪表盘、Inter、emoji、新图标库。
- 为「高级感」加无限循环动效或玻璃拟态。
- 把百科灌入从库里物理删掉来「变好看」。
- 新 ADR，除非动检索/生成/发布语义（本方案默认不动）。目录回答的**呈现**改模板即可，三道闸（ADR 0045）不改。

## 四、方案包（按插入优先级）

每包独立可演示、可单独成刀。Must/Out 写死，避免执行时膨胀成「顺便重做前端」。

### UX-A · 工作台可扫读（先做，纯观感也值）

**痛**：打开资产/商品/客服，第一眼是 CI 垃圾和 115 件未定价百科，演示主路径（保温杯/瓶装水/政策）找不到。

**Must**

1. 资产列表默认 tab = `待人洗`（无 `?status=` 时）。总览数字链接保持现有 `status=`。
2. 列表增加「工作队列 / 全部」开关（默认工作队列）：**首选按 `source_kind` 判（ADR 0025 血缘第一环）**——复核发现脏数据有干净信号：16 条 smoke/probe 全部 `source_kind='mcp_registered'` 且 `pending_review`；标题模式（`mcp-smoke` / `evidence probe`）只作收窄，不做唯一依据。`^未命名资产$` 不必进本规则（那是 4 条 `upload`+`published` 的 NULL 标题，前端兜底渲染；如要藏，走「标题为空」单独一条）。不删库。URL `?view=work|all`。
3. 资产列表加标题/ID 搜索（客户端先做；261 条现有一次拉全量）。
4. 商品页默认排序：已定价、有写回规格的在前；其余可折进「其余商品 N」。不要再给每张卡重复「写回只在发布时发生」。
5. 目录回落回答（`catalog_tools.py` 模板）：禁止 20 行未定价清单。改为「在售 N 件。已定价：{最多 8 条 名·价}。其余未定价，直接问商品名。」列举意图仍走工具、citations 仍空、闸不改（ADR 0045 列三道；代码实际四道——第 41 刀交接复核补了政策词闸 `_POLICY_RE`，`catalog_tools.py:49`）。**本项改的是回答模板（生成路径），按 goal §6.2.2 与 roadmap 排期纪律，须在 `docs/research/rag-eval-report.md` 记 before/after；模板确定性，预期零漂移，但必须留证。**
6. 客服会话列表：0 消息不显示为「进行中」；空会话折叠或自动关闭。顾客来源与操作者预览继续用现有徽章，不要混成一种。

**Out**：物理删除第 32–33 刀灌入；新后端检索；改 MCP 登记契约。

**验收**：干净库或工作队列下，资产首页能在一屏内看到待办而不是 `evidence probe`；客服「你们卖什么」不再出现 `Tesla 4001A` 这种 20 行 dump。

**前置（复核新增）**：先做数据卫生——这 16 条是 smoke/MCP 冒烟写入**演示库**的产物（id 1/2/246–259，246–259 连续），应先查冒烟脚本为何写演示库，并清一次或加标记（详见 §九 S4）。否则第 1 条把默认 tab 改成「待人洗」，操作者第一屏恰好落在 16 条 smoke 垃圾上。

### UX-B · 引用只读证据视图（产品故事核）

**痛**：点引用等于进编辑台，文档类还看不见原文。UX-NOTES §二.7 / ADR 0007 未兑现。

**Must**

1. `?v=N` 命中已发布版本时进入**只读证据模式**：横幅文案固定为「只读证据视图：引用指向 vN 的不可变快照。要改内容，请在待人洗版本上开修订。」
2. 主栏展示**该版本**正文。复用已有 `api.getVersionText`（今日只给 dialogue 用的 `TranscriptPanel`）。文档/素材/视频转写同样拉字节；加载/失败/空要有态。
3. 只读模式下隐藏人洗控件与「开修订」主钮；侧栏可留「去工作版本」次级链接（不带 `?v=` 或带当前待人洗版）。
4. 无 `?v=` 或 `v` 与工作版本相同：保持今天的治理编辑页。
5. 顾客通道引用芯片**不要长得能点进控制台**。可保留 `A-xxxx · vN` 只读展示；「没有帮助」留着，但不要做成蓝链。

**Out**：新证据对象；改引用写入；让顾客登录控制台。

**验收**：客服点芯片 → 看见该版原文、不能改字段、横幅在。从证据页回客服，会话还在。

### UX-C · 缺口补洞带上下文

**痛**：`那个多少钱？` 抽屉无会话、无商品、双提示条、标题=问句；tab「7」对表 9 行（混已解决）；同问「你们几点上班」开+已解决并存。

**Must**

1. 「去补文档」抽屉只留一条提示：问句 + 「发布后该缺口关闭」。去掉叠两条横幅。
2. 抽屉展示：原问、热度、最近会话链接（有 session_id 就给）、挂商品（能猜则预填，不能则空+说明「这条缺口没有商品」）。
3. 若已有可修订的已发布文档：先确认「开修订」还是「登记新文档」，禁止静默 `openRevision`（双击 409）。进行中按钮禁用。
4. 知识缺口 tab 默认只列 `open`；已解决用分段或二次开关，计数与列表同一口径。
5. 已解决的同一归一化问句再出现：回链到已解决缺口/资产，而不是让操作者以为要再补一份（归一化已有；UI 要把「已有口径」露出来）。

**Out**：改缺口关闭事务（ADR 0031）；目录意图漏进缺口若仍发生，记到 41 刀回归，不在本包扩词表。

**验收**：从 G-0010 打开抽屉能回答「补哪一句、挂不挂商品、登记还是修订」；tab 数字=可见待补行数。

### UX-D · 顾客停答与流式生命周期

**痛**：`/customer` 无 Stop/Esc；`useAskStream` 卸载不 abort；操作者页已有完整状态机。

**Must**

1. 顾客通道复用 `stop`：发送钮流式中变停止；Esc 停止；保留部分文本并标中断（与 `/service` 同文案族——工程实际文案是「已停止展示 · 完整回答已留档」，`MessageBubble.tsx:196`；原型 §二点八 写作「已中断」。开刀时二选一，不要新增第三种）。
2. `useAskStream` 在 unmount 时 abort。
3. 流式锁输入（已有）保持；停止后解锁。

**Out**：顾客会话回流；顾客端引用跳转。转人工表单是第 42 刀，本包不抢。

**验收**：顾客问长问题，点停止或 Esc，气泡标已中断，再问可发。离开页面后网络面板无继续 SSE。

### UX-E · 视觉回到 v3 + 去卡

**痛**：光泽 + 等宽卡 + 页头说明书 = 「AI 仪表盘模板」。第 43 刀若先做会再叠卡。

**Must**

1. `index.css`：去掉 body/panel/stat-card/btn-primary 的装饰渐变与 hover 位移。画布实色；面板白底+`line-2`；主钮近黑实色。圆角回到 4 芯片 / 6 按钮输入 / 8 面板（实现里 modal 10 / composer 12 / 气泡 14 是刻意的层级半径，收不收要在刀里显式说明）。**发送钮：保留 34px 圆形与流式原位替换——那是 UX-NOTES §二点八 的交互冻结项（「停止=Esc 或圆形按钮原位替换」）；只把品牌蓝渐变改为近黑实色（§二点七 色彩纪律要求蓝只做语义）。要改形状属解冻，需 Owner 明示。**
2. 总览：五张 `stat-card` 改成**一条可点摘要条**（数字+标签，不是磁贴）。步进器单行不折（步骤过多则横向滚动，不把第 4 步掉到下一行）。
3. 资产页：删掉 tab 下方三张重复统计卡。口径只留分段数字。
4. 所有 `PageHeader` desc 压到 ≤1 句职责。去掉「业务能力 ·」标题前缀、ADR 号、`confirmed QA`、`rubric`、`.env.example`、侧栏「可整包替换」可改为「演示店铺」。
5. 运营「投放发布」改为 `btn-secondary`；治理「发布」保持主钮。连接层政策条不用 `danger` 红底，改信息条。
6. 商品页：空规格不要撑一张表。有写回才渲染规格表；无写回的卡/行只保留名、类目、库存、价、编辑。

**Out**：新色板、新字体、图表库、深色 token 落地。

**验收**：对照 UX-NOTES §二点七表，主钮不是蓝、面板无内高光、资产页数字不出现两次。第 43 刀进来时总览只加趋势条，不加第六张等宽卡。

### UX-F · 薄页收口（契约证人页）

**痛**：素材/切片/考核/连接层/顾客空态读起来像切片残留。

**Must**（可拆两刀：F1 切片+商品表，F2 其余）

1. 切片：去掉灰底假视频（复核：`ClipsPage.tsx:146-150` 是灰底 + `FilmSlate` 图标 + 时码，**无播放器控件**，注释明写 v1 无视频字节）。改为表（ID / 商品 / 时码 / 转写摘要 / 状态 / 勾选）或保留卡但封面只显示时码文字，不要电影图标框。卡片内禁止 `C-` 与时码折成两行。
2. 考核：题库行明显可点（整行或「开始」）；「有标准答案」列**不恒真**（复核：`CoachPage.tsx:487-495` 条件渲染，兜底题显示「兜底题 · 无」），故保留或改列名，不要按「恒真」直接删。页头去 rubric 英文。
3. 连接层：`search_published` / `get_asset` 演示保留；`register_asset` / `export_published` 要么可点调用，要么标明「请用 MCP 客户端，本页不代发」。不要 2×2 说明书冒充四工具工作台。
4. 顾客空态：去掉「服务端签发一次性会话身份」；按钮与标题不要重复「开始咨询」。对话列表顶对齐，不要在巨大空白里漂。

**Out**：真 mp4/ASR（第 46 刀）；MCP 真连 Cursor（已有）；考核多轮扮客。

### 九点三、补充项（方案未覆盖，建议吸收）

- **S1 · UX-B 是唯一「grill 级」项，应单独成刀并优先。** 本阶段北极星是「产品立得住且经得起 grill」；「引用可核验」是核心主张，目前点引用落到可编辑草稿、文档看不到正文——这是 grill 会直接击穿的点。且成本最低（后端端点已通用，实证可取 doc 正文），收益/成本比全方案最高。建议 UX-B 独立一刀，排在 UX-A 之前或并列。
- **S2 · UX-C 不是纯前端包。** `knowledge_gaps` 表无 `session_id` 列、`KnowledgeGapOut` 无该字段、拒答路径 `product_id` 恒空（`knowledge_gaps.py:70-72`）。「原会话链接 + 商品猜测」需一并做后端小迁移（或在缺口创建时记录来源会话/命中商品）。UX-C 的 Out 段要显式写这条，否则执行时会卡住或静默降级。
- **S3 · 工作队列用 `source_kind` 判，不要只靠标题正则。** 复核发现脏数据有干净信号（16 条全 `mcp_registered`）。已在 UX-A.2 改。
- **S4 · 数据卫生是 UX-A 的前置。** 16 条 smoke/evidence 是冒烟链路写进**演示库**的产物（id 246–259 连续）。要么查冒烟脚本的目标准备库并改到测试库，要么给演示库做一次清理/加 `is_test` 标记；否则 UX-A.1 把默认 tab 改「待人洗」，第一屏正好是这 16 条。这条也是「真实现自我检查」的一部分——脏数据不该靠 UI 遮。
- **S5 · 补「干净库 / 首次运行」面貌。** 方案用「工作队列」遮测试数据，但没定义真实商家空库时每页长什么样（grill 会问「第一次打开看到什么」）。建议每个包加一条验收：干净库下图不空、话不假。
- **S6 · 每包验收纪律。** CI（build + lint + e2e）绿；改过的路径 1280 与 390 各出 before/after 截图；动到目录回答模板的包在 `docs/research/rag-eval-report.md` 记 before/after（§四 UX-A.5 已注）；CSS 收敛附 computed style 探针（沿用 visual-polish 先例）。
- **S7 · 写明规模假设。** 261 条全量拉取 + 客户端过滤可接受，但应写明阈值（如超 500～1000 转服务端分页）并留 TODO，避免「一万条怎么办」无话可答。
- **S8 · a11y 提升为通则。** 新抽屉、停止钮、工作队列开关必须键盘可达且 Esc 可关（UX-G 只覆盖部分页面），建议写进每个包的验收。

### 九点四、一处冻结线冲突（开刀前须 Owner 裁决）

UX-E.1 原写「发送钮改回 `btn-primary` 方钮，禁止 34px 蓝圆」。但 `prototype/UX-NOTES.md` §二点八明确「停止=Esc 或**圆形按钮原位替换**」+「composer 卡片化（… 34px 圆钮）」，而 §四声明「交互与状态机冻结」。**圆形+34px+原位替换属冻结交互，品牌蓝属颜色纪律**——两者可拆开处理：保留形状、只把颜色从品牌蓝改为近黑（§二点七：蓝只做语义）。本文件已按此订正；若 Owner 确实要改成方钮，那是解冻，需显式说明并同步改 UX-NOTES。
