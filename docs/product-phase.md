## 1. 范围

### 做

- 目录：`E:\code\ecommerce-ai-suite\prototype`
- 纯前端：Vite + React + TypeScript（与 ADR 0011 控制台一致，方便以后搬交互，不搬 mock）
- 客户端路由（React Router 即可）
- **一份** mock store（模块级内存 + `localStorage` 可选）。客服、考核、素材、切片、微调、MCP 演示页读的是同一批商品/资产 ID，禁止各页一份 JSON
- 八块都有可点入口；中台治理是枢纽，不是一个「设置」页
- 空态、失败态、禁用发布、拒答，都要能点出来，不只做成功路径

### 不做

- 不调 LLM、不调 embedding、不调对象存储、不调 Postgres
- 不写 `apps/api`、`packages/platform`、`compose.yaml`（那是工程刀）
- 不发明品牌名（不要「北纬优选」）；种子店名用中性词如「演示店铺」，放在 mock 数据里
- 不把 MCP 做成第八个并列大业务首页；它是连接层，用「连接层」页面或抽屉
- 不实现真实微调训练；只 mock 导出任务和客服里的「基座 / 微调」开关
- 不拆八个独立站点

## 2. 视觉与 UX 约束

这是**商家侧操作台**（内部工具 / 中等密度数据界面），不是 landing、不是 AI 聊天玩具。

- 禁止：紫粉渐变、玻璃拟态全铺、三列功能卡首页、Inter+slate 默认套、emoji 当图标、虚构科技公司名
- 允许：清晰侧栏、状态标签（已接入 / 待人洗 / 已发布）、表格+详情、对话里的引用芯片
- 用词必须跟 `CONTEXT.md` 走：操作者、顾客、资产、登记、发布、修订、引用、弃权、写回、连接层。不要写「知识库」当中台整体，不要写「用户」
- 两种「发布」必须在 UI 上分得开：治理台的**发布资产** vs 运营 Agent 的**投放发布（mock）**
- 桌面为主（≥1280），窄屏（390）可导航、可走完关键路径，不要求表格完美

## 3. 信息架构（必须有的路由）

侧栏按业务，中台靠前：

| 路由 | 名称 | 谁用 |
| --- | --- | --- |
| `/` | 总览 | 三条闭环的入口卡，点进去是真路由不是死按钮 |
| `/platform/assets` | 中台 · 资产 | 按三态筛选、登记、待人洗队列 |
| `/platform/assets/:id` | 资产详情 | 版本、抽取字段、弃权、发布、修订 |
| `/platform/products` | 中台 · 商品 | 规格来自已发布写回 |
| `/service` | AI 客服 | 操作者预览顾客对话 |
| `/ops` | 运营 Agent | 工具轨迹 + 投放确认 |
| `/materials` | 素材中心 | 生成任务，成品登记为资产 |
| `/clips` | 直播切片 | 候选列表，拣选后登记 |
| `/coach` | 销售考核 | 从已发布对话资产抽场景 |
| `/finetune` | 模型微调 | 只从已发布导出；客服可切模型 |
| `/connect` | 连接层 | MCP 工具列表：检索/取资产/登记/导出；**没有 publish** |

总览必须能一句话点到三条闭环，不要八个同等大小的营销磁贴。

## 4. Mock 数据（开工先写死这一份）

至少：

- 商品 2 个（例如瓶装水和保温杯），含可写回字段：净含量、保质期
- 资产：
  - 1 份**已发布**规格文档（有版本 v1，字段已写回商品）
  - 1 份**待人洗**规格文档（保质期弃权/空，净含量已抽出）
  - 1 份**已接入**失败件（机洗失败原因可见）
  - 1 份**已发布**售后政策（不挂商品）
  - 1 份**已发布**对话资产（供考核）
  - 1 份待人洗对话（客服检索不到）
- 会话：客服页可新开；结束后可「回流登记」→ 新资产状态=已接入
- 素材任务 1 条已完成，回流资产=已接入（未发布）
- 切片候选 8+ 条（mock 即可，不必真 20 条视频），拣选后登记已接入
- 微调：无运行中任务；导出按钮只勾选已发布

所有列表项能点进详情。ID 稳定，引用格式展示为 `资产ID · vN`。

## 5. 必须做对的 UX 逻辑（功能 mock，规则真）

用同一 store 的 reducer 实现，不要只改文案。

1. **三态可见性**  
   治理台能看见三种状态。客服检索、考核抽题、微调导出、连接层「检索」工具，只命中已发布。待人洗/已接入出现在这些表面时，应是空结果或明确「未发布不可用」，不是半透明还能点开当证据。

2. **机洗 / 弃权**  
   待人洗详情里字段可空，空字段标「弃权 / 原文未找到」，禁止自动填一个「12个月」。发布按钮：规格文档在保质期或净含量仍空时**禁用**，并写明缺哪项。

3. **发布与写回**  
   点发布：状态→已发布，当前已发布版本指针更新，商品页对应字段更新。未点发布时商品页仍是旧值。

4. **修订**  
   已发布资产上「开修订」：产生待人洗新版本，列表里当前已发布版仍可被客服引用。修订发布后指针前移。同时只允许一个修订。

5. **客服**  
   - 问已发布规格：回答 + 引用芯片（资产 ID + 版本），点芯片到资产详情（只读已发布版）。  
   - 问只有待人洗里才有的错值：拒答或转人工，不引用待人洗。  
   - 问库存：mock 工具调用条（不是 RAG）。  
   - 结束会话：「回流登记」生成已接入对话资产，**不能**直接已发布。

6. **运营 Agent**  
   可见步骤：读商品卖点 → 调素材 → 生成投放文案。中断/重试可点。最后「投放发布」要二次确认。这条不改变资产三态（除非素材回流登记）。

7. **素材 / 切片**  
   生成或拣选成功 = **登记**到已接入，进入治理队列。页面上写「未发布，客服还不能用」。

8. **考核**  
   场景下来源必须是已发布对话资产 ID。回放页能看到引用。

9. **微调**  
   导出向导默认只列出已发布。客服页有「基座 / 微调」切换（mock 两套口吻即可）。任务记录有「导出资产 ID 列表」。

10. **连接层**  
    工具：检索已发布、取资产、登记、导出已发布集。界面上**没有**「发布」工具。演示一次「外部 Agent 检索」只返回已发布。

## 6. 开发节奏（Goal 模式）

按垂直路径做，做完一条立刻用浏览器验一条，不要先画完八个空页再点。

| 顺序 | 路径 | 做完即验 |
| --- | --- | --- |
| P0 | 壳 + 总览 + mock store + 中台列表/详情 | 三态筛选、详情字段 |
| P1 | 待人洗 → 禁用发布 → 补字段 → 发布写回商品 | 清单 B |
| P2 | 开修订；客服问规格带引用；问未发布则拒答 | 清单 C |
| P3 | 会话回流登记为已接入 | 清单 C 回流 |
| P4 | 素材登记、切片拣选登记 | 清单 D |
| P5 | 运营 Agent 轨迹 + 投放确认 | 清单 D |
| P6 | 考核抽已发布对话 | 清单 E |
| P7 | 微调导出 + 客服切模型 | 清单 E |
| P8 | 连接层无 publish、检索仅已发布 | 清单 F |
| P9 | 总览三条闭环走通 + 窄屏抽查 | 清单 A + 清单 G |

发现 UX 不合理（多点一次、状态看不懂、两种发布分不清）：**当场改原型**，不要开新 ADR，除非和已锁领域冲突。若冲突，停下来写进 `prototype/UX-NOTES.md`，不要擅自改领域。

## 7. 浏览器验证（强制，写入 Goal 的验收）

执行 Agent **必须**用内置浏览器，不要只看编译成功或截一张图。每条路径：打开 → 点击 → 断言界面文案/按钮状态 → 必要时刷新看 store 是否还在（若用了 localStorage）。

建议：`npm run dev` 后打开 `http://localhost:5173`（以实际端口为准）。

### 视口

- 桌面：1280×800 全量清单  
- 窄屏：390×844 至少走完：总览 → 待人洗发布写回 → 客服引用 → 连接层看不到 publish

### 清单 A · 壳

1. 侧栏八块+中台都能进，没有 404、没有死按钮。  
2. 总览三张闭环卡点进去是对应路由。  
3. 界面无虚构品牌名、无「知识库」当中台标题、无 MCP 当一级「第八个产品」。

### 清单 B · 治理（核心）

1. 资产列表能按已接入 / 待人洗 / 已发布筛选，三类都有样本。  
2. 打开待人洗规格：至少一字段为弃权/空。  
3. 必填仍空时「发布」禁用，有缺项说明。  
4. 补全必填后可发布；商品页该字段变成新值。  
5. 未发布前商品页不是这份待人洗的值。  
6. 已接入失败件看得到失败原因，不能当已发布检索。

### 清单 C · 接待闭环

1. 客服问已发布商品规格：有回答，有 `资产ID · vN` 引用，点击到达该资产已发布版。  
2. 客服问仅存在于待人洗的内容：拒答或转人工，引用区没有待人洗 ID。  
3. 开修订后，客服引用仍是旧已发布版本号，直到修订发布。  
4. 结束会话 → 回流登记：中台出现新资产，状态=已接入，客服检索仍搜不到它。

### 清单 D · 内容闭环

1. 素材「生成」完成：新资产已接入，不在客服检索里。  
2. 切片拣选至少 1 条：同上，已接入。  
3. 运营 Agent 能看到多步轨迹；刷新或点重试不丢叙事。  
4. 「投放发布」有确认；取消则不出现已投放状态。

### 清单 E · 能力闭环

1. 考核选题只能选已发布对话资产。  
2. 微调导出列表默认没有待人洗/已接入。  
3. 客服切换「微调」后回复口吻或徽章变化（mock 即可）。  
4. 导出记录能看到资产 ID 列表。

### 清单 F · 连接层

1. 工具列表含检索、取资产、登记、导出。  
2. **没有**发布工具。  
3. mock「外部检索」结果只有已发布资产。  
4. mock「登记」产生已接入资产，不产生已发布。

### 清单 G · 回归与窄屏

1. 走完 C 再打开商品页、资产列表，ID 仍一致（没有模块私藏数据）。  
2. 390 宽：能打开侧栏或等效导航，能完成「补字段发布」和「客服看到引用」。  
3. 关键按钮可点区域够大，没有被侧栏挡住。

**失败处理：** 任一条失败 → 改代码 → 从该条所属清单开头重跑，不要只复测失败那一下。全部通过后在 `prototype/README.md` 记下：视口、日期、哪几条曾失败后已修。
