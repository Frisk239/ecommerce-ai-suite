# ADR 0051：图片活化口径（图片描述=检索文本面 / VLM 只出草稿人确认生效 / 证据面生图仍 Out）

- 日期：2026-09-16（第 94a 刀）
- 状态：接受
- 相关：ADR 0003（字节只住对象存储）、0010（confirmed 才进索引）、0033（密钥只经 env、空凭证降级）、0035（LLM 草稿与人洗）、0038（字节不动、出口必掩）、0042（负向生命周期出口）、0047（video 正文走 transcript 字段、对象键跟字节走）、0050（ASR env 三件与「空 key = 不发请求」）；词条「图片描述」「资产种类」「素材库」；roadmap `docs/roadmap-system-completion.md` 第 94a 刀

## 背景

「资产种类」词条第 147 行从第一天就写着图片，但产品里没有一条图片能进中台的路：登记端点只收文本（kind=document），检索文本面只从版本字节切块——**图片字节是原图，解不出 UTF-8，进不了索引**。于是三件事同时缺：运营传的商品图无处可放；顾客问图片内容词（「有没有带支架的显示器」）永远无命中；94b 的媒体引用无从起步。

第 46 刀为 video 解过同构的题（字节是 mp4 二进制 → 正文改由 `transcript` 字段承载、永不读字节），本刀把这套口径推广到图片，并回答一个 video 没回答的问题：**模型生成的描述，什么时候算数**。

## 决定

### 1. 「图片描述」是图片资产唯一的治理字段，也是它唯一的检索文本面

- `machine_wash_field_names("image", product) == ["图片描述"]`，与是否挂商品无关——图片不跑商品规格正则（字节是二进制）。**同一个字段集同时是人洗 PATCH 的合法集合**：描述必须可确认，否则人洗无路可走。
- **索引切块只从字段进**：`index_chunks_for_version` 对 image 永不读对象字节（video 46 刀裁决 5 同款；回归网是 `_ExplodingStorage` 纯单测，任何一次读都炸）。
- **索引只认 confirmed**（0010）：VLM 草稿即便发布也不进索引——顾客面前不出现未经人确认的模型文本。这与 video 允许回落 extracted 的 46 刀口径**刻意不同级**：video 的 transcript 是资产自身音频的转写（机洗预置即正文），image 的描述是**生成**内容——生成内容必须人确认才生效。
- **正文出口回落**：`read_version_text` 对 image 回落「图片描述」（confirmed 优先、extracted 次之），覆盖 MCP `get_asset` / `export_published` 与版本正文端点（46 刀 P0 的教训：正文出口全都要收，否则一份图片资产把整条读链路带崩）。**无描述的图片资产仍然报错**（409 / 工具错误），不静默返回空串——空正文会被读成「这份图没有内容」，而真相是「描述还没人写」。
- 正文供体字段（video 的 transcript / image 的图片描述）**不再另补「字段名：值」块**：正文块就是该字段的文本，再补一块等于同一句在索引里存两份（图片的描述是确认的常态路径，双份证据会在 prompt 的 2 个证据位上互相挤占）。

### 2. VLM 只出草稿：env 三件、data URL 内联、失败=缺草稿（不是机洗失败）

- `VLM_API_KEY` / `VLM_BASE_URL` / `VLM_MODEL`，OpenAI 兼容 `POST {base}/chat/completions`，messages 带 `image_url`（**data URL 内联 base64**——内部对象键厂商读不到，内联是唯一不引入「先把图传公网再让模型取」的形态）。密钥纪律同 0033/0050：只从 `.env` 读、不入库、不进日志与异常文案。
- **空 key = 不建客户端、不发请求 = 无草稿**：上传照常登记、照常待人洗，人洗补写描述（fail-诚实，不假成功也不静默降级）。
- 草稿写 `extracted_fields["图片描述"]`（`source=machine`，人确认才转 confirmed），≤20s 超时、0 重试（同机洗纪律）。
- **失败（超时/坏输出/字节不是可识别图片）恒弃权**：不把资产扣在已接入、不写 `last_error`——描述是**增值项不是登记的前置**（与 dialogue「已配置但失败=机洗失败」不同级：那里失败等于这轮机洗没有产物；这里失败只是少了一张草稿，人洗本就兜底）。
- 登记路由由 `async def` 改为同步 `def`：图片登记会在请求内进 VLM 看图（阻塞 HTTP ≤20s），事件循环线程上不许有阻塞调用（与切片真切、ASR 提音轨同纪律）；`file.file.read()` 与 CSV 批量导入同款。
- 草稿值落库前过 `redact`（0038 出口必掩：模型可能把图中可读的号码原样带进描述）。
- **图片上限 10MB**（文本 2MB 不变）：原图不是正文，手机拍一张常 3–5MB。字节魔数**复验**——报 `image/png` 传 jpeg 的键写 `.jpg`、传普通文本直接 415（键与字节恒一致，46 刀裁决 4）。

### 3. 图片来源：运营上传为主（本刀）；辅轨与洗帧归后续刀；**生图恒 Out**

- 本刀只开**上传通道**：`POST /api/assets/register` 按 content_type 分派 kind（文本→document、png/jpeg/webp→image），对象键后缀跟字节走；`PUT …/versions/{n}/bytes` 按**资产种类**收字节（图片可换图、重跑草稿；video 仍 409）。
- `spec_schema` 补 `图片`（Wikidata P18）/`官网`（P856）两个**可选**字段位（审计 18 归位，数码四类）——只登记字段位，**不做** Wikidata 批量拉图。
- Pexels 辅轨与直播洗帧（94c）归后续刀；**AI 生图维持 Out**（goal §7）：证据面的图片只来自「人拍/人传/从自己的直播里洗」。

### 4. 商品素材聚合是派生视图（不建独立页、不落表）

- `GET /api/products/{id}/assets`：按挂载关系取资产行，形状复用 `AssetOut`（与 `/api/assets` 同契约）；废弃资产不出现（0042 同口径）。
- 前端在**商品卡**上加「素材」段（商品维度即店铺的素材库入口）：图/视频/文案/其他分组，**已发布在上（唯一权威口径）、未发布灰标**；懒加载——折叠不发请求，展开才拉一次（商品页是卡片墙，逐卡预取 = 首屏请求数等于商品数）。

## 动机

「多模态素材」是懂王口径 8+1 里此前最薄的项（只有素材文案生成 + 切片视频）。图片活化把它补成一条真链路：**人传商品图 → 机器出草稿 → 人确认 → 顾客问图上的话命中带引用**——同一套三态治理、同一套引用纪律、同一套字节纪律，不新造对象、不新造状态机。生图 Out 与图片活化 In 并不矛盾：**证据要能核，图要么是人拍的、要么来自可追溯的素材源**。

## 后面

- **Out**：AI 生图；Pexels 辅轨拉图与 Wikidata 批量拉图（使用剧本）；洗帧（94c）；媒体字节端点 `GET /api/customer/assets/{id}/media`（94b）。
- **Debt**：真 VLM 验收需 `VLM_API_KEY`（仓库不带；closeout 记降级口径——本机无 key 时以 mock 集成测试 + 无 key 路径实跑替代，真 key 由 Owner 补）。
- **Debt**：草稿**重生成无独立端点**——只有登记/换字节/（已接入态的）重试会重跑；待人洗资产想重新出草稿要走换字节。VLM 故障恢复后的批量补草稿留后续刀。
- **Debt**：`read_version_text` 的图片回落含 extracted——按 ID 读一份「只有草稿」的已发布图，MCP 会看到未确认草稿（检索面不受影响：索引只认 confirmed）。这是 46 刀「正文出口都要收」与「草稿不算数」之间的已知取舍，收紧需先给「版本正文」定义「无正文」的合法态。
- **Debt**：video 资产的规格字段面板与字段闸门分派不一致（面板按商品 spec_schema 铺行、闸门只认 `machine_wash_field_names`，点确认会 422）——图片在本刀收口（不显示规格面板），video 的历史形态未动。
- **Debt**：`VLMUnavailable` 弃权只进服务端日志，人洗台看不出「为什么没有草稿」（UI 文案统一为「未出草稿 · VLM 未配置或调用失败」）——要分开需给前端一个配置状态端点（同 93 刀 `/clips/asr/status` 形态）。
- 测试：`apps/api/tests/test_vlm.py`（形状/客户端契约/草稿三态）、`test_retrieval.py`（图片正文只从字段进、草稿不进索引）、`test_registration.py`（字段集/键后缀/登记三态）、`test_mcp.py`（正文回落与错误形态）、`test_image_integration.py`（上传闸门/草稿/确认发布命中引用/素材聚合/换图，真 PG）。
