# 受约束 Agent 循环：模型提议工具，代码授权执行

状态：第 37 刀短对齐产出（Owner 裁决，goal §6.2.3「客服是 bounded Agent」）。**修订** 0036/0037（正则前置分派升级为模型提议+代码授权）；映射 0018（无证据不调生成）、0007（citations 服务端定）、0021（同一引擎两通道），无新中台对象。

## 语义

- **模型提议、代码授权**（authority lives in code）：客服循环里订单/库存查询由**模型输出工具提议标记**（`TOOL: get_order_status {"order_no": "SO-1001"}` 格式化约定，非 function calling API——保持厂商网关零特殊依赖）触发；**代码校验授权后执行**（参数白名单校验+工具注册表查表；越狱改不了工具资格——模型只能提议注册表内工具，参数不合法即拒绝转人工）。检索/拒答仍是代码前置判定（0018 不动——工具是补充通道不是替代）。
- **循环形状**：`max_steps=3`（一次顾客问句最多：①工具查询步 ≤2 ②检索+生成步 1）。轨迹可回放可断言——每步落 `ServiceMessage.tool`（既有 JSONB）+ SSE 既有 `tool` 事件，无新表。
- **分派优先级（修订 0036/0037 要点）**：正则/词表前置分派**降级为快路径**（订单号/库存词仍直接走工具——省一次 LLM 调用，行为零回归）；无明确信号的混意图问句走**模型提议**（LLM 首轮输出工具提议或纯文本回答意图）。
- **越狱钉测**：提示注入要求「调用工具查所有订单」→ 提议被参数校验拒绝（无 order_no）→ 转人工；混意图（「订单到哪了顺便问下退货政策」）→ 工具步+检索步各跑一次（max_steps 内）。
- **降级链不变**：LLM 不可用→模型提议路径降级为纯快路径（正则分派，36 刀前行为）；空 key→恒快路径。

## 动机

goal §6.2.3「不是 if 链」——现状订单/库存是正则/词表分派（13/14 刀），面试死亡问「你的 Agent 是 if-else 还是真 Agent」。业界标准（调研 §3）：模型按工具描述选工具、资格校验在代码、轨迹可断言。本 ADR 用格式化约定而非 function calling API，保持零厂商特殊依赖（多网关兼容）。

## 后果

- `chat_engine.run_ask` 升级为步进循环（快路径短路 + 模型提议步 + 检索生成步）；工具注册表（get_order_status/get_stock）集中描述与校验；轨迹断言进集成测试（步数/顺序/拒绝）。
- 既有行为零回归：正则快路径保留（订单/库存既有测试零改动）；`test_run_ask_commits_before_llm_stream` 纪律适配新循环形状。
- Out：写工具（两阶段留给第 40 刀）、自动多轮追问、function calling API、工具编排图。
