# ADR 0052：媒体引用口径（media_citations=服务端按引用派生的姊妹键 / 媒体端点只出已发布指针版 / query 令牌只开一个端点且日志脱敏）

- 日期：2026-09-16（第 94b 刀）
- 状态：接受
- 相关：ADR 0003（字节只住对象存储）、0004（只有已发布可检索）、0006（已发布指针版）、0007（引用带版本）、0021（顾客与控制台同一引擎）、0038（出口必掩）、0047（video 正文走字段、键后缀跟字节走）、0051（图片活化：描述=检索文本面、生图仍 Out）；词条「媒体引用」「引用」；roadmap `docs/roadmap-system-completion.md` 第 94b 刀

## 背景

证据面已经完整、字节面仍是断的：46 刀起切片视频可被检索命中（转写进索引），94a 起商品图可被命中（描述进索引），但回答只有**文本 + 引用芯片**——顾客问「有带支架的显示器吗」拿到一句描述，看不到那张图；命中的那段切片视频，也没有任何可播的出口。引用（0007：资产 ID + 版本号）已经指向对的证据，缺的是两件事：**载荷里声明「这条回答带媒体」**，以及**一个能取到字节的端点**。

顾客通道的工程约束把这个端点定死：`<img>`/`<video>` 的 `src` **带不了请求头**（浏览器规范）——顾客发问走的 `Authorization: Bearer` 在附件场景用不上。

## 决定

### 1. `media_citations` 是 `citations` 的姊妹键：服务端按同一份证据派生，模型无决定权

- 形状 `[{asset_id, version_no, mime}]`，**恒为列表**（无媒体= `[]`，不是可选键——形态固定，前端按键直取）。SSE `complete` 两通道同形状（媒体不是内部 id：顾客要拿它去取字节）。
- **派生点唯一**（`services.media.media_citations_for`）：输入是服务端定的 `citations`（0007，模型无引用决定权），输出只认命中的 image/video。派发发生在**所有会改写 citations 的闸之后**——覆盖声明收口（第 58 刀）与实体存在性闸（第 82 刀）把 citations 清成 `[]` 时，媒体必须跟着空：不会出现「拒答却挂一张图」。
- **mime 从「资产种类 + 对象键后缀」常量表取**（png/jpg/jpeg/webp → `image/*`、mp4 → `video/mp4`），不嗅字节、不听模型。两个条件都要：后缀在表内（字节真是媒体）**且** mime 家族与资产种类一致。**旧切片资产（kind=video 但键是 `.txt`、字节是时间码文本）不是媒体**——不产引用，端点上也不可播（不按 kind 冒充 mp4，是 46 刀「键后缀跟字节走」的延伸）。
- **随消息落库**：迁移 0031 给 `service_messages` 加姊妹列 `media_citations`（nullable JSONB；agent 行回填 `'[]'`，customer 行 NULL，与 citations 同口径）。重载会话由它还原图/播放器——与 `gap_id` 那种「运行时返回、消息表不加列」刻意不同：媒体附件是回答的一部分，寿命与 citations 同。

### 2. 媒体字节端点：只出当前已发布指针版、双通道鉴权、不暴露对象键

`GET /api/customer/assets/{id}/media`（双通道；操作者预览与顾客页共用同一 URL）。

- **只出已发布**：取 `assets.current_published_version_id` 指向的那一版。未发布（待人洗）/已废弃/非媒体资产/指针为空/对象缺失——一律 **404 同一文案**「媒体不存在」：不泄漏存在性（id 探测无反馈面），**不区分「没有」与「不可出」**（对齐 goal 口径：未发布拒绝）。**响应不回对象键**（字节只经此端点出，键不出门）。
- **图片直出**：`Content-Type` 按后缀（同一张常量表）、`Content-Length` 精确。
- **视频支持单段 Range**：`bytes=a-b` / `a-` / `-n` → `206` + `Content-Range: bytes a-b/size`；语法合法但越界/倒置/`-0` → `416` + `bytes */size`（RFC 9110 §14.1.2）；多段/单位不对/字面坏头 → **忽略**（200 全量，不假装支持 `multipart/byteranges`）。
- **流式**：`ObjectStorage` 端口加 `size` / `iter_bytes`（本地实现 64KiB 分块，`seek` 后逐块 yield）——视频可达数百 MB，Range 响应不整读进内存。416/206 的判定先用 `size` 算好再开流。
- 响应带 `Accept-Ranges: bytes`、`Cache-Control: private, no-store`（URL 带令牌，不让中间层/浏览器留副本；代价是拖动会重复拉区间，内网演示可接受）、`X-Content-Type-Options: nosniff`。
- **顾客令牌不设会话状态闸**（active/ended 都放行，registered 亦然——只要令牌未过期）：附件是「本次会话已经收到的回答」的一部分，结束会话不该让图裂。发问要 active，取自己收到过的附件不要（两回事）。

### 3. query 令牌只开这一个端点，且日志侧脱敏

`src` 带不了请求头，两条出路：**query 令牌**，或先 `fetch` 成 blob 再 `objectURL`。**选 query 令牌**：

- blob 形态每个附件都要前端写一遍取字节/对象 URL 生命周期管理，且**视频 Range 拖动直接失去 HTTP Range 的好处**（blob 整段进内存才可播）——与本刀「流式不整读」的取舍正面冲突。
- query 令牌的泄漏面写在这里：URL 会进访问日志与浏览器历史。收口：**日志管线一个 structlog 处理器**（`observability.redact_query_tokens`）把 `?token=`/`&token=` 的值替换成 `***`——uvicorn 的 access log（stdlib 记录）与本进程所有 `logger.*` 走同一条处理链，故这是服务端日志的**全部出口**（调用点会漏，链上不会）。**边界**：只此端点接受 query 令牌；发问/反馈/评分/联系方式仍只认 `Authorization: Bearer` 头（少一个暴露面）。
- 令牌按 DB 等值查行（不是 `_authorize_customer_session` 的「按会话 id 查 + compare_digest」）：端点对「令牌错/过期/不存在」统一 401 同文案、且响应内容只依赖 `asset_id`（与令牌身份无关），探测面为零；换来 `src` 能带凭证。
- 已知取舍：**持有任一有效会话令牌即可按 id 取任意已发布媒体**（不校验「这条媒体属于你的会话」）——已发布媒体本就是跨会话公开的引用物，未发布/已废弃 404 是唯一硬边界。

### 4. 渲染：媒体附件区与引用芯片区并列

- 共享 `MessageBubble`（0021：客服预览页与顾客页同一视觉语言）：`image/*` → `<img>`（限宽圆角、`loading="lazy"`）；`video/*` → `<video controls preload="metadata">`（点开才拉字节，首帧不预载整段）。
- 顾客页媒体 URL 带 query 令牌（`api/client.mediaUrl` 单一出处），操作者页不带（同源请求自动带会话 cookie）。
- **媒体附件区与引用芯片区并列**：芯片是「依据哪份资料的哪一版」，附件是「那份资料里的图/视频本身」。旧的附件在资产被下架后自然裂图/不可播——这是「只出已发布」的如实表达，不做前端缓存兜底。

## 动机

多模态证据面在此闭合：引用说「依据 A-0501 · v1」，媒体附件把这份证据的**字节**端到顾客眼前——顾客问图上的东西能看见图，问切片转写能播那一段。纪律一条不改：生图仍 Out（0051：可引用媒体只来自人传的图与切片/直播视频）、未发布不出（0004 在字节面同样成立）、引用由服务端定（模型对「回答里出现哪些媒体」零决定权）。

## 后面

- **Out**：94c 洗帧（帧是独立资产，走 94a 治理后再进媒体引用）；MCP 侧导出媒体字节；Range 多段/断点续传/转码/HLS。
- **Debt**：媒体端点**不设限流**——IP 闸（30/60s）会误伤「一条回答带两张图」的正常路径，未发布 404 与已发布集合是当前唯一边界；真部署应在反代层按 IP/令牌限带宽（README 已记）。
- **Debt**：query 令牌的寿命与令牌 TTL 同（24h）——日志已脱敏，**浏览器历史/Referer 之外的泄漏面未清**（`Referrer-Policy` 由反代定；仓内 dev 栈无）。
- **Debt**：附件没有标题/来源说明（只有 `alt` 与 `title` 的 A-xxxx · vN），也没有「展开原图/下载」——顾客面先要「看得见」。
- **Debt**：`read_version_text` 与媒体端点是两条独立读取路径（正文=文本面、媒体=字节面）；一份「已发布但字节被清」的资产在正文侧报 409、媒体侧 404，两侧错误口径暂不统一（都在诚实报错，未合并）。
