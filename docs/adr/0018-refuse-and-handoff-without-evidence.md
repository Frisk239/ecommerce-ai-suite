# 无已发布证据则拒答并转人工；工具失败不拿检索顶

无命中若仍凭模型常识回答，中台权威被绕开。拒答却继续聊，转人工没有闭合。低置信还引用，考核和评测回放会被脏证据污染。库存问题若改去翻文档，会把「有货」答成规格原文。

规格先读商品字段，开放叙述走中台检索。两者都没有或低于拒答阈值 → 拒答并转人工。库存和订单只走工具，工具失败 → 转人工，不检索。阈值数字工程标定；规则是无证据不答。

## 修订（第 66 刀）：什么算「有证据」——评论证据的适用域

「无已发布证据则拒答」隐含一个前置问题：**命中了算不算证据**。审计刀 13 C 轴
P0-2 实测：顾客评论（review_import）里「到货后看着很多」词法撞上「到货了吗」
（短评论块 bigram 少、分数天然高 0.4–0.5，**分数阈值分不开**——金标真命中最低
才 0.17），引擎据此引用英文 account_access 评论回答了到货问；「退货运费多少钱」
首引衣服评论（0.447 压过退货政策 0.408）。

裁决（域规则，非阈值）：**顾客评论是商品体验证物，不是服务状态的证据**。问句
命中服务状态词（到货/发货/物流/快递/收货/签收/退货/退款/运费/订单/单号）且**无**
观点标记（怎么样/值得/评价/靠谱/推荐…）时，评论块不作为证据——剩下的命中照旧
（退货政策问该答政策文档，它现在是首引）；评论全被滤掉即无证据 → 拒答+转人工+
缺口（问 fulfillment 状态本就该这样）。

观点标记豁免是零回归的关键：金标 19 条期望评论资产的 case **全部**带观点标记
（问的就是评价本身，评论正是对的证据），大集复跑逐位相同（70.0/65.0）。

落点在 `retrieve()` 内（候选 SQL 随带 source_kind，join 本来就在）：引擎、缺口
新鲜度检查、MCP search_published、评测 runner 全出口同语义——「什么算证据」只
有一处定义。带订单号的问句在引擎步 1 已被订单工具接走，到不了检索。
