# 实体存在性闸（OOV）与两类分说

状态：审计刀 17 补账 ADR（2026-09-16）——第 82 刀引入判定、第 86 刀定两类语义、
第 85 刀缓存化，三刀当时均未立 ADR（流程欠账，本篇回溯固化既有行为，不引入新
语义）。映射词条「拒答」（无证据不答）+「知识缺口」（知识待补）+ 0045（目录
回落——商品行作为非证据数据源的同族先例）。

## 语义

- **实体存在性闸**：RAG 检索有命中、模板可组装出回答的问句，若点名了**库内
  不存在的实体**（判据：剔观点尾与字段词后，实体段 ≥4 字连续零出现 + 对候选
  资产标题最高亲和为 0；语料 ≥100 行护栏，小库不判），不引他品证据、不调
  模型，收口为拒答（`fallback_reason=oov`），缺口/工单走既有出口。
- **两类分说**（86 刀 Owner 裁决）：拒答文案与缺口归宿按「实体是否对应本店
  在售」区分——
  - **在库资料缺**（实体命中库内商品名/类目名，`oov_product_match`）：文案
    「商品资料还在补充中」；**落知识缺口**（确实是知识待补）且**挂上该商品**
    （审计刀 17：词法命中是可靠归属）；建工单。
  - **不在库**：文案「本店暂时没有这款商品」；**不落缺口**（补文档补不出来，
    缺口池不被经营范围问题污染）；仍建工单（需求信号/销售线索，Owner 裁决）。
- **判定范围**：只在检索有命中的 answer 路径判——目录/工具/澄清/转人工路径
  提前 return 不属其语义；**检索零命中的拒答不判**（词法无法区分「库外商品」
  与「非商品知识问」，保守落缺口是设计取舍，见「边界」）。

## 动机

82 刀症状：问「雀巢咖啡的配料」（库内无此商品）引花生酱/雪糕的资料作答——
跨商品幻觉的词法根因（零出现实体 + 演示语料的边际命中）。86 刀订正：顾客
点名未上架商品是必然且高价值的意图信号，问题不在被问到而在**回应方式**——
用系统内部语言（「已发布资料里没有…」）打发，且没查商品表。

## 后果

- `oov_product_match` 判据（双向语义不同）：实体串 ⊂ 库内名任意长度（顾客用
  简称）；库内名 ⊂ 实体要求库内名 ≥3 字**且覆盖率 ≥0.6**（防「小米电视机
  顶盒」被「电视机」片段误命中）；类目/别名按「真有商品的类目」过滤。
- 性能（85 刀）：语料快照按「库身份 + (id, 指针, 标题) 摘要 sha1」缓存，发布/
  改标题/废弃/换库即失效；商品表匹配直查不缓存（商品新建/改名立即生效）。
- 边界（记债，审计刀 17 B-P1-1 裁决）：零命中问句的缺口归宿不做商品/知识
  区分——扩闸会把「会员积分怎么兑换」类知识问句误判成「本店没有」（误判比
  漏检贵，审计刀 12 口径）。
- 测试：判据四类病例 + 覆盖率 0.6 边界（含恰好等于）+ 缓存失效四向 + 两类
  分说的缺口/工单/挂商品钉子（`test_oov_gate.py`）。
