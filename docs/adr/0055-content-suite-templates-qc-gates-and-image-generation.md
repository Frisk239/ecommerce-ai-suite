# ADR 0055：自媒体内容套件（模板参数非 Agent / 配图=素材成品非证据 / 质检双闸独立记录 / IMGGEN fail-closed 跳过）

- 日期：2026-09-16（第 98 刀）
- 状态：接受
- 相关：ADR 0028（不做微调、生成只走厂商 API）、0029（质检过线才登记）、0033（密钥纪律）、0038（素材任务生命周期）、0050/0051（ASR/VLM 的 env 三件与空 key 语义）、0053（帧=独立图片资产、人工拣选闸门）；词条「任务」「质检」「内容模板」「生成配图」；roadmap `docs/roadmap-system-completion.md` 第 98 刀

## 背景

素材中心（17 刀）只有一种产物：站内卖点文案。自媒体运营需要三种形态（站内投放
文案/小红书笔记体/短视频口播稿）且小红书/口播天然要配图。同时 0038 的质检只有
一道规则闸+人抽检：规则四条全是形状检查（非空/长度/含商品名），拦不住「净含量
990ml」这类与规格矛盾的**事实性幻觉**——LLM 生成的营销文案最危险的失败模式
恰恰是这一类（编参数、夸功效）。

## 决定

### 1. 模板是 prompt 参数，不是 Agent

`POST /api/material/tasks` 收 `template`（station/xhs/short_video，默认 station
=17 刀形态）。三模板只派生两样东西：生成的 system prompt 风格段（小红书=emoji
口语种草+话题标签；口播=开场钩子-卖点分镜-行动号召）与配图的 prompt/尺寸。
**不加 planner、不建新模块、不进运营编排**（运营不是 Agent 的既有裁决不动；
ops 的 `gen_material` 编排步是另一条独立通道，本刀不碰）。

### 2. 配图=素材成品，非知识证据（分层红线）

- `with_image` 请求时按模板派生 prompt 调文生图（`services/imggen`，OpenAI
  兼容 `POST {base}/images/generations`，`b64_json` 取字节；默认硅基流动
  FLUX schnell）。尺寸按模板：站内=方图 1024x1024、小红书=封面竖版
  768x1024、口播=竖版背景 768x1024。
- **配图登记为独立 image 资产**（不是素材资产的版本字段——字节不是文本；
  同 0053「帧=独立资产」先例）：kind=image、source_kind=`material_generated`
  （0025 枚举既有值，不新增）、标题 `{商品} · {模板名}配图`、挂同商品。
  抽检通过一次登记**双资产**（material+image），回执两个资产 id；配图未
  生成/跳过=单资产。
- 配图字节抽检前住对象存储 `material/` 前缀暂存键（**不是资产**，同
  clip_recordings 先例）；登记时转正、暂存键删除。
- **红线**：生成图是营销素材成品，不是商品外观的知识证据——不回写商品规格
  （image 机洗只出「图片描述」，天然不碰规格字段）；「图片描述」预填文案首句
  摘要（VLM 看图草稿可用时优先——机器弃权时预填兜底，人洗可改，94a 治理），
  描述说的是「这是这条文案的配套图」，发布与否由人洗决定。94a 时代「AI 生图
  不做」的 Out（证据要能核）按此分层解除：生图可以做素材，不做证据。

### 3. 质检双闸 + 人抽检，两闸独立记录

- **第一道（既有）**：`qc_check` 四条纯函数规则，0038 不变。
- **第二道（本刀）**：**LLM 事实性质检**——文案+商品规格事实给 LLM（同机洗
  调用模式：`asyncio.run(complete_chat)`，线程池前提），只问三类问题：与规格
  矛盾/夸大功效/编造参数；输出钉 JSON `{passed, issues[]}`。判定不过、调用
  失败、输出不可解析一律 **fail-closed**：任务 failed（last_error 记 LLM 闸
  原因）、不进待抽检、文案保留预览面、可重试。写作风格/emoji/话题标签明确
  排除在问题域外（否则二道闸会误杀小红书模板）。
- **独立记录**：规则项进 `last_error`、LLM 判定进 `material_tasks.qc_llm_passed`
  列（None=未跑到——规则闸先挡下时不调 LLM，不给「LLM 质检过」的假象）。
- **第三道不变**：人抽检（approve 才登记）。双闸过线只是进待抽检的资格。

### 4. IMGGEN fail-closed：无 key 诚实跳过，不 fail 任务

`IMGGEN_API_KEY/BASE_URL/MODEL` 三 env（同 ASR/VLM 形态；空 key=不建客户端、
不发请求、密钥不进日志与异常文案）。与 ASR/VLM 的 **409 拒绝**刻意不同级：
配图是增值项不是任务本体——无 key 时配图步**诚实跳过**（`image_status=
skipped_no_key`，任务详情如实标注「未配置 IMGGEN_API_KEY，跳过」），纯文案
套件照常走完全链。文生图失败（超时/坏字节）同样不 fail 任务（`failed` 状态
如实记录，可整任务重试再要图）。双闸没过线不跑配图步（不给废文案产图）。

配图字节按魔数复验（vlm.image_mime 同一张表）：厂商返回的不是可识别
png/jpeg/webp = 失败，不拿坏字节冒充配图。

## 动机

「运营建任务 → 选模板 → 文案+配图 → 双闸质检 → 抽检 → 登记发布」是把素材
中心从单文案工具升级为内容套件的最小真形态。二道闸补的是规则闸的结构性盲区
（事实性），且与「顾客面前不出现未经人确认的模型文本」的治理主线同构：LLM
质检拦幻觉、人抽检终审、登记后照常机洗人洗发布。配图的分层红线让「AI 生图」
在不污染知识证据面的前提下进入素材供给。

## 后面

  gen_material 独立通道不动）；配图重生成单步（整任务重试代替）；多图。

  的放弃残留口径，登记路径已清）；`GET /tasks/{id}/image` 预览端点服务暂存
  字节（登记后 404，长期看可换成资产详情内的预览统一）。
- 测试：`apps/api/tests/test_material.py`（模板派生/LLM 闸/配图三态纯函数
