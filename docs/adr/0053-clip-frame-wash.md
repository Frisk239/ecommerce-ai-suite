# ADR 0053：直播洗帧口径（均匀采样+VLM 打分而非转写时间戳 / 候选是请求态不落库 / 确认即登记、全自动被否）

- 日期：2026-09-16（第 94c 刀）
- 状态：接受
- 相关：ADR 0014（候选不是资产）、0015（只登记资产不造任务）、0025（来源种类）、0026（血缘是派生视图）、0033（密钥只经 env、空凭证 fail-closed）、0047（切片真链路：ffmpeg 纪律与键跟字节走）、0050（ASR 的「空 key = 端点 409」）、0051（图片活化：描述=检索文本面、VLM 只出草稿）、0052（媒体引用）；词条「直播洗帧」「图片描述」「素材库」；roadmap `docs/roadmap-system-completion.md` 第 94c 刀

## 背景

素材面的图片至此只有一条进路：运营手动上传（0051）。但店铺最大的图片产地是**自己的直播**——46 刀起切片视频是真 mp4 资产，93 刀起有云转写；一场直播里商品被拿起、展示、特写，这些画面天然是商品素材图。「洗帧」就是把它变成素材：**直播 → 切片 → 帧 → 素材库 → 客服引用出图**，内容自循环闭合。

intake 初稿假设可以「按转写句时间戳定位候选帧」——查实后不成立：**资产的 `transcript` 是纯文本字段，没有时间戳**（时间戳只活在 `clip_candidates` 的 timecode 两列里，且候选行登记后就与资产脱钩，无行可查）。按句定位没有数据可用，编不出来。

## 决定

### 1. 候选帧定位 = 均匀采样 + VLM 打分（不是转写时间戳）

对已发布视频**每 5 秒抽一帧**（采样数上限 24：超上限把间隔拉大到 `duration/24` 保持均匀覆盖全程——掐尾会漏掉直播后段的展示帧），每帧送 VLM 打分（prompt：是否清晰的商品展示画面，返回 1-10 分 + 一句话），**分数 ≥6 的帧成候选，上限 8**（超出取分高者，展示按时间序）。打分用缩略图（宽 ≤480px jpeg）——判「清不清晰、是不是商品帧」不需要全尺寸。

- 时间戳定位被否的根因如上（transcript 无时间戳）；顺带的取舍：采样不理解内容，「主播低头理货」的帧靠 VLM 打分淘汰，不靠语义定位。若未来给 transcript 加句级时间戳，可再评估换定位策略——那是另一刀。
- 打分复用 94a 的 VLM 客户端（同一把 `VLM_API_KEY`、同一超时/密钥纪律），但**不共用 prompt**：打分（帧好不好）与描述（图里是什么）是两个任务（`vlm.chat_with_image` 供自定提示，`describe_image` 原样不动）。打分输出钉 JSON `{"score", "note"}`，解析失败=该帧无分跳过（不编造）；VLM 请求失败=502。
- **无 VLM key = 候选端点 409**（fail-closed，同 0050 ASR）：打分没有本地兜底，无 key 就没有候选；`GET /api/clips/frames/status` 给前端禁用判据（同 asr/status 形态）。

### 2. 帧候选是请求态：不落库、不落对象存储

**零新表零新行**（0014「候选不是资产」的同性质延伸）：`POST /api/assets/{id}/frame-candidates` 请求内 ffprobe 时长 → 采样 → 逐帧 ffmpeg 缩略 → 逐帧 VLM 打分 → 过滤，缩略图以 **base64 data URL 回传**，全程不写任何持久层。刷新即重算——洗帧无副作用，**幂等性只由「确认登记」这个写动作承载**（多洗一次只是多花一次算力，库里不会堆东西）。

- 不建 `frame_candidates` 表的根因：切片候选落库是因为它是**多日工作队列**（转写一次、慢慢拣）；帧候选是**一次会话内的即时预览**（洗完当场拣完），生命周期等于请求。为它建表等于给「右键另存为」建数据库。
- 候选没有 id：确认请求只回传 `at_second`，**服务器从已发布版字节重新抽全尺寸帧**——不信任请求里的缩略图（缩略图是 VLM 打分的输入，不是资产字节；伪造请求也造不出比真帧更好的资产）。

### 3. 确认即登记：独立图片资产走 94a 通用治理，全自动被否

`POST /api/assets/{video_asset_id}/frames`（body `{at_second, vlm_note?}`）：

- 字节 = 该秒**全尺寸** jpg（ffmpeg 输入侧 seek，`-ss` 在 `-i` 前；0047 已订正越界会吸附末关键帧——抽不出帧就 422 如实失败，不做 ffprobe 时长硬闸）；
- `register_asset(kind=image, source_kind="clip_frame")`：**来源枚举加值零 DDL**（0025 应用层常量无 DB CHECK，0026/0028 先例确认），挂商品透传源视频资产的 product_id，标题 = `{商品/视频名} · 实拍帧 mm:ss`；
- **走 94a 通用治理**：登记即跑 image 机洗——VLM 出「图片描述」草稿（专用 prompt，与打分提示词不同任务）→ 人洗确认 → 发布 → 94b 媒体引用可出图。`vlm_note`（候选阶段打分附注）**不冒充描述草稿**，只进日志；
- **全自动被否**：登记的只是「待人洗的图片资产」，不自动确认描述、不自动发布——发布权在人（0005）。批量自动登记（洗完 ≥6 分全登记）同样被否：VLM 的 6 分是机器判断，操作者勾选是人工闸门（与切片拣选同构，0014）。
- **血缘最小形态**：查实 audit_log 无备注列且**登记动作从无留痕先例**（register/upload 均不写 audit——留痕是治理动作不是登记动作），故不写 `action="clip_frame"` 的 audit 行；溯源由三处既有数据承载——`source_kind=clip_frame`（0026 血缘视图 origin 环自动显示）、标题（实拍帧 mm:ss）、回执 `cut_from`（「切自 A-xxxx · vN」，0047「回执指名切自哪份」同款）。
- 入口闸：非视频资产 422；未发布 409（只有已发布指针版可洗——0004 口径在洗帧面同样成立）；**键后缀不是 `.mp4` 的旧时间码文本切片 422**（ffmpeg 对文本字节抽不出帧，入口说清而不是深处炸含糊错误；0052「不按 kind 冒充 mp4」同口径）。确认端点不判 VLM key——确认不打分（描述草稿无 key 恒弃权，人洗兜底）。

### 4. 前端：入口在已发布视频资产的详情页

侧栏「治理动作」加「洗帧到素材库」按钮（无 VLM key 禁用+提示；修订中也可用——读的是线上指针版字节）→ 抽屉：开始洗帧（同步请求，分钟级）→ 候选网格（缩略图+分数+时间点+VLM 一句话，点击勾选）→「登记所选帧」→ 回执列表（新资产 A-xxxx + 标题 +「切自」锚，链接直达治理台补描述/发布）。

## 动机

多模态素材的「来源面」在此补全：图可以是人传的（0051 上传），也可以是**从自己的直播里洗出来的**——两者共用同一套字节纪律（键跟字节走）、同一套治理（描述草稿→人洗→发布）、同一套引用（94b 出图）。证据要能核：洗帧的每一步（哪份视频、哪一秒、几分、谁确认）都有如实承载，全自动被否守住「发布权在人」的底线。

## 后面

- **Out**：批量自动登记（≥6 分全登记）；按转写句级时间戳定位帧（先得有带时间戳的 transcript）；Pexels 辅轨拉图（0051 已记 Out）；抽帧重编码/超分/去字幕。
- **Debt**：候选重算不可免（刷新即重算）——一场直播反复洗帧每次都全量打分；要缓存就得给候选找落点，与「请求态」决定冲突，真有性能痛再开刀。
- **Debt**：逐帧 VLM 打分是串行同步请求（≤24 帧 × 正常 1-3s/帧，最长分钟级）——操作者等在请求里（与真切/转写同纪律）；超时单帧由 vlm 的 20s 纪律兜底。
- **Debt**：确认登记没有重复闸（同一秒可登记两份资产，键不同）——与 pick 的 CAS 占位不同类：`at_second` 是自由参数不是共享行，操作者闸门（前端勾选+回执可见）是当前唯一防线。
- 测试：`apps/api/tests/test_frames.py`（采样/解析/过滤/标题纯函数）、`test_frames_integration.py`（闸门码位/真 ffmpeg 抽帧/VLM 替身打分/确认登记/描述草稿/发布命中引用全链，真 PG）。
