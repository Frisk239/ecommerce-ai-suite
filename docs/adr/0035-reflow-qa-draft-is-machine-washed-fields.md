# 回流对话机洗抽 QA 草稿：QA 对是对话资产的结构化字段，不是新资产

状态：第 12 刀短对齐产出（Owner 裁决，调研 §6 候选 2）。映射 0009（结构化抽取允许弃权）+ 0017（发布切块入索引）+ 0013（登记带字节）+ 0012（机洗不是任务），无新中台对象、无新来源种类、无新资产状态。

## 语义

- **机洗按资产种类分字段集**（词条既有授权「按资产种类抽结构化字段」）：文档类挂商品 → 商品 spec_schema；**种类=对话 → 字段集就是 `qa_pairs` 一个字段**，值 = `[{q, a}, ...]` 数组（转写中抽出的问答对草稿，LLM 生成）。
- **`extracted_fields` 的 value 允许结构化值**（JSONB 本就支持）：`qa_pairs` 的 value 是数组，不是字符串；弃权仍是 `{abstained: true}` 单形状——「无可抽 QA」「未配置模型」都算弃权，不加 reason 分叉。
- **LLM 失败分级**：
  - **未配置（空 `LLM_API_KEY`）= 降级不失败**：跳过 QA 抽取，`qa_pairs` 弃权，对话资产照常推进待人洗——即回到第 3 刀行为（整段转写资产）。CI 空 key 环境与既有回流测试零改动。
  - **已配置但失败/超时/输出不可解析 = 机洗失败**：停已接入 + `last_error`，走既有就地重试端点（与解析失败同模式）。
- **发布闸门不变**：对话没有规格必填（词条锁死），`qa_pairs` 弃权或空数组都可发布；发布后转写正文照旧按轮切块（第 3 刀行为保留）。
- **人洗口径**：操作者在治理台确认/改写/删/增 QA 对 → `confirmed_fields.qa_pairs = {value: [...], source: "human"}`；**只有 confirmed 的 QA 对在发布时成块入检索索引**（每对一块「问：{q}\n答：{a}」），未确认的机洗草稿不进索引。
- **不自动登记新资产**：QA 草稿不拆成独立文档资产（拒绝对方案 B）——那需要新来源种类（动 0025 枚举）、资产爆炸、血缘复杂化；对话资产一条版本同时携带转写正文与 QA 字段，引用仍锚 `A-{id}·v{N}`。

## 动机

调研（`docs/research/demo-to-product-gaps.md` §2.3/§6 候选 2）：业界（AI Knowledge Assist、Zendesk Knowledge Builder）从历史对话抽 QA → 人审入库，是冷启动补知识的标准工艺；本仓库会话回流已通，但「整段对话直接当 dialogue 资产，检索粒度粗」。机洗「按资产种类抽结构化字段」的模式复用过来：对话种类的字段就是 QA 对——同一登记/机洗/人洗/发布/切块链路全复用，零新对象。

## 后果

- 登记回流对话的请求在配置了 LLM 时会多等一次生成（≤20s）；回流是操作者低频动作，不伤顾客面。README 记一笔。
- 聚组/聚类、多会话批量抽、PII 打码（词条「机洗含打码」在代码中尚不存在，现状即无）不进本刀，留后续。
- 治理台需补对话正文查看（人洗必须能看见转写——现状 dialogue 资产「没东西可看」）与 QA 对编辑器。
