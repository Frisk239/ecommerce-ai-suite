# 订单工具：只读 get_order_status，数据源不升格、分派在代码、失败转人工不检索

状态：第 13 刀短对齐产出（Owner 裁决，调研 §3/§6 候选 3 + ADR 0018「库存和订单只走工具，工具失败→转人工，不检索」的实现落地）。映射 0018（工具失败不拿检索顶）+ 0002（订单和库存不升格）+ 0024（工具失败转人工不产生缺口）+ 0021（顾客不做订单账号），无新中台对象、无新来源种类。

## 语义

- **订单表是工具数据源，不是中台对象**（0002 落表）：`orders` 表（单号/状态/商品行/物流事件）只被订单工具读，不进检索索引、不可登记/发布/引用/导出，不进治理台；不与商品/资产产生外键语义。种子幂等灌 mock 单（演示店铺语境，与「库存可 mock」同口径）。
- **分派在代码不在 prompt**：问题文本命中订单号模式（`SO-\d+`，大小写不敏感）→ 走工具，**跳过检索**；不命中 → 既有检索路径原样。订单号=知识型凭证（0021 顾客无账号），业界同款 `get_order_status(order_id)`。无单号的订单问题走现状检索→多半拒答转人工（无凭证即转人工，语义正确）。不做 LLM 意图分类。
- **工具成功 → 模板组装，不调 LLM**（v1）：订单状态是结构化数据，确定性组装最诚实（AI Knowledge 工具返回也以结构化为先）；`citations` 恒空——订单不是资产，不可用 `{asset_id, version_no}` 引用（0002/0007）。LLM 组织语言留后续刀。
- **查无此单 / 工具故障 → 转人工**：消息 kind 用**新值 `"handoff"`**（不复用 `"refusal"`——refusal 分支连带 `record_refusal_gap`，0024 锁死工具失败不产生缺口）；`handoff=True`、`citations=[]`、**不检索**（0018）；content 含结构化交接摘要文本（单号、失败原因——词条「转人工 v1 只是消息种类，没有坐席队列」）。
- **SSE 新事件 `tool`**：`{name, arg, result}`——工具调用条数据；状态行复用 `thinking`（「查询订单中…」，第 7 刀多 thinking 先例）。complete 载荷加 `tool` 字段，操作者/顾客同形状（单号本由提问者提供，无内部敏感字段，不走 gap_id 式白名单裁剪）。
- **两通道同权**：分派插在 `run_ask` 引擎级（检索之前），操作者预览与顾客通道自动同获；顾客限流三闸不动（一问至多一工具调用，不放大）。

## 动机

词条「转人工」承诺「库存/订单工具失败时同样发生，不拿检索顶」，但订单工具不存在——拒答转人工是唯一触发源，词条只兑现了一半。业界（调研 §3）get_order_status 是客服工具的最小标准形状：只读、资格校验在代码、结构化返回、显式转人工触发器、交接带结构化摘要。

## 后果

- `orders` 迁移 0007 + 种子；README/UI 文案教顾客带单号提问（建议问题按钮）。
- 库存工具（词条同段承诺）显式留下一刀，同模式复用；email+zip 凭证查询、两阶段写操作（check_eligibility/create_return）、坐席队列、LLM 组织工具语言均 Out。
- `test_run_ask_commits_before_llm_stream` 的 commit 序列对**非订单问题**必须零漂移（分派是前置正则，不命中零成本）；订单路径新序列单独钉测试。
