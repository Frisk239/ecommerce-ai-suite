## 任务状态机（词条「任务」修订：见下）

词条原句「状态为排队、进行中、失败、可重试」中「可重试」读作**属性**而非状态。任务完整状态集：

```
queued（排队）→ running（进行中）→ pending_qc（待抽检：规则质检已过线，等人）
                                   ↘ failed（规则不过/生成失败——可重试）
pending_qc → registered（抽检通过，成品已登记为资产，终态）
pending_qc → failed（人工打回——可重试）
```

- **同步就地执行**（0012 无任务表 worker 先例=机洗）：建任务 API 请求内完成 LLM 生成+规则质检（≤20s），queued/running 是落库可见的瞬时态；失败/待抽检是稳定态。
- **失败不进中台**（0029）：failed 任务不登记任何字节；registered 才写对象存储。
- **重试**=failed 任务上一键重跑（新一次生成，同任务行状态回 running）。

## 生成与质检

- **生成物 v1=商品卖点文案**（文本素材）：操作者选商品 → LLM（`complete_chat` 复用）按商品名+规格生成「标题+正文」；空 key=任务失败（素材生成没有降级模板——生成是任务的本体，不像问答可回退）。
- **规则质检（代码不在 prompt）**：非空、总长 ≤2000、标题非空、正文必含商品名。不过 → failed（last_error 记规则项）。
- **操作者抽检**：任务详情看生成文案预览 → 通过（登记）/ 打回（failed，原因=人工打回）。
- **登记**：`register_asset(kind=material, source_kind=material_generated, content=文案)`——已接入→机洗（素材无字段集，弃权推进待人洗）→人洗→发布→可检索可引用（与资产三态无缝衔接）。

- 机洗管线加 `redact` 纯函数：手机号 `1[3-9]\d{9}`→`1****\*\*\*\*\d{2}`、邮箱本地部→`****`。作用于两处：**LLM QA 抽取的 prompt 输入**（转写送厂商前打码——修外流面）与**抽出的字段值**（q/a 里的 PII）。版本字节不动（对象键不可变锁死）。
