# Goal

本仓库做一套**通用的电商 Agent 体系**：八个项目覆盖售前、内容、运营、销售、模型迭代；**数据中台是核心**；内部走中台接口，MCP 只把中台暴露给外部 Agent。

它是可复用的能力套件，不是某家虚构公司的内部系统。店铺、商品、聊天、直播只是中台里的数据；换一批数据，同一套系统照样跑。仓库名 `ecommerce-ai-suite` 说的就是这件事。

一句话：八个项目是一套 Agent 体系的八块业务能力；数据中台是核心；MCP 是对外连接层。

---

## 1. 这不是什么

- 不是「数据中台主线」再顺带做几个应用。中台不讲业务故事，业务 Agent 才讲。
- 不是给某一家店定制的人设工程。不设虚构品牌、不扮演「某公司 AI 老大」——那是面试时可选的口述角度，不是产品身份。
- 不是八个可以拆开投不同岗位的玩具仓库。拆开之后，面试官会问数据从哪来、新系统怎么一天接上、RAG 撞墙之后怎么办——答不上来就是 demo。
- 不是传统数仓/指标平台的缩小版。这里的中台服务的是 Agent：要检索、要引用、要导出微调集、要给 MCP 当工具，而不是只出报表。
- 不是把 LangChain / RAG / Agent / 微调名词堆进 README。每个模块必须能演示一条真人能走完的路径。

---

## 2. 解决什么问题

对象是**有商品、客服、运营、直播、销售团队的电商业务**（店铺、品牌站、代运营都算），不是某一家店。典型数据散落在 IM、网盘、表格里。这套体系要通用地接住这些事：

1. 客户问商品特点、规格、售后口径时，AI 客服按中台知识回答，而不是靠值班同事背话术。
2. 运营要图、文、短视频时，不必每次从零找设计。
3. 一场 15 分钟直播能切出二三十条可投放切片。
4. 销售上岗前用真实聊天场景过考核，而不是念 PPT。
5. 客服回复质量碰到 RAG 天花板时，从同一份数据里导出微调集，把更好的底座模型送回客服。
6. 以上任何一块要接新系统时，走的是「中台数据 → MCP/提示词 → 系统」，而不是「再挖一张库、再开一个月需求」。

这六件事必须共享同一份被治理过的数据。这就是中台作为核心的理由。类目、店铺名、商品样例都是可替换的种子，不写进产品身份。

---

## 3. 体系怎么咬合

八个项目全部在一个仓库里。它们是电商业务的八块能力，共用一份数据契约，不是八个产品线。

```
                    真实聊天 / 商品资料 / 直播录像 / 素材成品
                                      │
                                      ▼
                         ┌─────────────────────────┐
                         │  ④ 数据中台（核心）        │
                         │  接入 → 机洗 → 人洗 → 补全 │
                         │  统一资产、统一血缘、统一检索 │
                         └────────────┬────────────┘
                                      │
              ┌────────── 中台接口（内部） / MCP 连接层⑦（仅外部 Agent） ──────────┐
              │                       │                         │
              ▼                       ▼                         ▼
       ┌────────────┐         ┌──────────────┐          ┌────────────┐
       │ ① AI 客服   │◄─RAG───│ 高质量知识/对话 │──导出───►│ ⑧ 模型微调  │
       │            │         └──────────────┘          │            │
       │ ◄── 微调后的底座模型 ───────────────────────────┘            │
       └────────────┘                                               │
              ▲                                                     │
              │ 真实对话也回流中台                                    │
              │                                                     │
       ┌────────────┐         ┌──────────────┐                      │
       │ ⑥ 销售考核  │◄─场景───│ 中台对话资产   │                      │
       └────────────┘         └──────────────┘                      │
                                                                    │
       ┌────────────┐    调用    ┌──────────────┐                    │
       │ ② 运营Agent │─────────►│ ⑤ AI 素材中心 │──成品回流中台───────┘
       └────────────┘           └───────▲──────┘
                                        │ 切片汇入
                                ┌───────┴──────┐
                                │ ③ 直播切片    │
                                └──────────────┘
```

读图规则：

- **业务主线**是电商落地：接待客户 → 生产并分发内容 → 培训销售 → 模型变好再服务客户。
- **数据中台**是核心枢纽：所有输入经过治理，所有输出可被下一系统引用。
- **MCP** 不是第八个业务，也不是模块总线。内部 ①②③⑤⑥⑧ 走中台接口；MCP 只给外部 Agent 发现和调用同一套接口。没有对外连接层，中台只是又一个后台。
- **数据可替换**：种子目录里的店铺/商品只用于演示；系统不依赖任何一个品牌名。

## 4. 八个项目各自必须证明什么

编号按业务发生顺序，不是开发顺序。每个项目都要能单独演示，也必须能指出它从中台读了什么、写回了什么。

### ① AI 客服

- **业务**：客户咨询（商品卖点、规格、售后口径）先由 AI 接待。
- **在体系中的位置**：中台知识的第一个消费者；对话日志是中台最重要的回流。
- **必须有**：RAG（带引用）、多轮、转人工/拒答、工具查询（库存/订单级至少 mock 到可演示）。
- **面试要能讲**：检索从哪来、为什么不是把商品页塞进提示词、答错时怎么追溯到哪条资产。

### ④ 数据中台（核心）

- **业务**：文本、图片、视频、聊天记录进入后，经过机器清洗 + 人工清洗 + 人工补充，变成可被 Agent 使用的资产。
- **在体系中的位置**：唯一的数据权威。知识库不是中台的别名；知识库是中台对外的一种视图。
- **必须有**：资产登记、血缘（从哪来、被谁用、洗成什么样）、检索、导出（给 RAG / 给微调 / 给考核）、人工工单。发布权只在治理台；连接层不能发布。成熟后可按种类考虑自动发布，默认关，第一版不做。
- **面试要能讲**：没有中台为什么接新系统要一个月；有了中台为什么「提示词 + MCP」一天能出系统。这句话必须能对着仓库里的接口讲，不能只写在 README。

### ⑤ AI 素材中心

- **业务**：按商品批量生成文案、宣传图、短视频脚本/成片（生成能力可按成本降级，但流水线不能假）。
- **在体系中的位置**：读中台商品与卖点，写回成品素材，供运营 Agent 调用。
- **必须有**：任务、版本、引用了哪条商品知识、质检（至少规则 + 抽检）、回写中台。
- **面试要能讲**：素材不是聊天窗口里「帮我做张图」，而是可复用的资产。

### ② 运营 Agent

- **业务**：运营人员用自然语言驱动「选品卖点 → 调素材中心 → 拼投放文案/日历」。
- **在体系中的位置**：素材中心的调用方，证明内部 Agent 经中台接口编排工作，而不只是问答。对外演示「一天接新系统」才走 MCP。
- **必须有**：可观察的工具调用轨迹、失败重试、人工确认后再「发布」（发布可 mock）。
- **面试要能讲**：Agent 编排、长链路断了怎么办——这是「Demo 还是生产级」的死亡问。

### ③ 直播切片

- **业务**：直播录像自动切出可投放短片段（目标量级：15 分钟出 20+ 条候选）。
- **在体系中的位置**：切片作为素材汇入素材中心，再进中台。
- **必须有**：转写、按话题/高潮切、打商品标签、人工拣选后入库。
- **面试要能讲**：切片为什么要进中台（可检索、可复用、可被运营 Agent 调用），而不是留在本地文件夹。

### ⑥ AI 销售考核

- **业务**：销售上岗前用真实客户对话场景做模拟考核，而不是背标准答案。
- **在体系中的位置**：中台对话资产的第二种用法（第一种是客服 RAG）。
- **必须有**：从中台抽场景、AI 扮演客户、按维度打分、留下可回放记录。
- **面试要能讲**：同一份聊天数据如何服务两个系统（客服学习 + 销售考核），这就是中台作为核心的现场证据。

### ⑧ 模型微调

- **业务**：当 RAG 解决不了口吻、拒答边界、类目口径时，从中台导出清洗后的对话/知识对做微调，再把适配后的底座提供给客服。
- **在体系中的位置**：闭环的最后一跳：数据 → 模型 → 业务。
- **必须有**：导出格式、训练任务记录、前后对比评测、在客服里可切换「基座 / 微调」。本地可用 LoRA / 小模型或记录完整离线流程；禁止只写「调用了微调 API」而没有数据集血缘。
- **面试要能讲**：什么问题不该微调（知识过期、事实变更走中台更新）、什么问题才该微调。

### ⑦ MCP 与 Agent 实战（连接层）

- **业务**：把中台能力暴露成工具，让 ①②③⑤⑥⑧ 以及未来第九个系统用同一套协议接入。
- **在体系中的位置**：贯穿层，不是独立业务。
- **必须有**：中台 MCP（检索、取资产、登记回流、导出数据集），包的是同一套中台接口；至少一种外部 MCP 客户端能连上。内部模块不经 MCP 互调。
- **面试要能讲**：新系统 = 提示词 + 选哪些 MCP 工具；内部为什么不走 MCP。对比传统「新库 + 新接口 + 新联调」。

## 5. 三条闭环（讲故事只用这三条）

1. **接待闭环**：聊天进入中台 → 治理成知识 → 客服 RAG 回答 → 新对话再回流。
2. **内容闭环**：商品知识 → 素材中心生成 → 直播切片汇入 → 运营 Agent 分发 → 成品再进中台。
3. **能力闭环**：RAG 不够 → 中台导出微调集 → 微调底座 → 客服切换模型 → 效果对比写回评测。

面试 30 分钟只讲这三条，比报八个仓库名有用。不必编一个公司人设。

---

## 6. 完成标准

仓库完成，当且仅当下面全部为真：

1. **一个仓库、一套可替换的种子数据、一个可运行的控制台**，八个项目都有入口，而不是八份 README。
2. **中台是唯一数据权威**：客服、考核、素材、切片、微调的演示数据都能指出中台资产 ID；禁止各模块私藏一份互不同步的 JSON。
3. **MCP 可被至少一种外部客户端连上**，工具列表能被模型选中；本仓库自己的 Agent 走中台接口，不经 MCP。
4. **每条业务路径可演示**（人能点、或脚本能跑），并且能回答「数据从哪来、写到哪去」。
5. **简历只写一个主项目名称**，八个模块作为职责展开；README 提供 3 分钟口述稿（三条闭环、中台为什么是核心、MCP 如何让新系统变快）。口述可以带业务例子，但不绑定虚构品牌。
6. **死亡三问有代码对应**：编排可见、失败可重试或可转人工、检索无命中时拒答而不是幻觉。
7. **产品表面没有虚构公司名**。种子数据若需要店名，放在 `data/seed/`，可整包替换。

## 7. 明确不做

- 不接真实淘宝/抖音商家后台（用可替换的种子业务数据演示）。
- 不把产品做成「某某优选 AI 部门」；界面、仓库、简历主标题都用通用名。
- 不自研基础大模型；微调证明「数据→模型→业务」闭环，不证明预训练。
- 不做完整数据仓库主题域、不写实时数仓论文。
- 不为了凑技术名词引入第二套 Agent 框架。
- 不把八个项目做成八个部署单元才算「像大厂」；先保证同仓可跑、契约清晰，再谈拆服务。

## 8. 简历怎么用这套东西

主项目名称建议（可改，含义不能改）：

> 电商 AI Agent 体系（数据中台 + MCP 连接层）

展开时按业务职责写，不按框架写，也不按虚构公司写：

- 负责数据中台：多模态资产治理、血缘、检索与数据集导出
- 负责 AI 客服：中台 RAG + 工具调用 + 人工兜底
- 负责素材与运营 Agent：生成流水线经中台接口编排；MCP 给外部 Agent 复用同一能力
- 负责直播切片回流与销售考核：同一份对话/录像资产的第二种用法
- 负责微调闭环：中台导出 → 评测 → 客服切模型

技术栈写在职责后面，绑定结果，不单独开「技能清单」糊弄 HR。

## 9. 词必须统一

| 用这个 | 不要用这个 | 为什么 |
| --- | --- | --- |
| 电商 Agent 体系 | 中台主线、八个 demo、某某公司 AI 部门 | 体系是通用产品，中台是核心 |
| 数据中台 | 知识库（当整体）、数据湖、数仓 | 知识库只是中台的一种视图 |
| 资产 | 文件、语料、素材（当中台对象时） | 中台里登记的是资产，素材是业务成品 |
| 连接层 / MCP | 第八个业务系统、模块总线 | MCP 只对外，不与客服并列抢戏 |
| 回流 | 保存、导出一份副本 | 强调写回中台、可被下一系统引用 |
| 底座模型 | 我们的大模型 | 微调的是适配后的底座，不是自研预训练 |
| 种子数据 / 店铺 | 产品名、品牌人设 | 店名只存在数据层，可整包替换 |

垂直域是**电商**（客服、直播、素材、销售都绑在这条链上）。通用指的是不绑死某一家店，不是做成行业无关的空壳平台。
