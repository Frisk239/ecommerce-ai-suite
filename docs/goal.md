# Goal

本仓库做一套**通用的电商 Agent 体系**，给求职主项目用：写进简历要让人眼前一亮；面试不演示，30 分钟只口述、对代码提问，必须讲得清、经得起 grill。

它不是七个并列的生产模块，也不是 LangGraph 玩具，也不是给面试官点的演示站。它是一份**被治理过的知识平面**，上面跑一个**受约束的客服 Agent**，再用 MCP 把同一份已发布权威暴露给外部 Agent。七块能力共用一份数据契约；深度故意不均——① 客服、④ 中台、⑦ 连接层是主线并加厚；②③⑤⑥ 是契约证人，能指到同一个资产 ID 即可。

店铺、商品、聊天、直播只是中台里的数据；换一批种子，同一套系统照样跑。仓库名 `ecommerce-ai-suite` 说的就是这件事。不设虚构品牌，不扮演「某公司 AI 老大」。

一句话：中台是权威；客服是 bounded Agent（模型提议、代码授权）；MCP 只对外；知识变好靠发布，不靠训练；评测有数字才许谈 RAG 质量。完善度用代码、测试、评测报告证明，不靠点屏幕。

形状（入口、契约、三条能讲的路径）已在第 27 刀达成。当前目标是把形状做成**可答辩的体系**。施工顺序见 `docs/roadmap.md`。

## 1. 这不是什么

- 不是「数据中台主线」再顺带做几个应用。中台不讲业务故事，业务 Agent 才讲；但业务 Agent 必须读同一份已发布指针，否则就是 demo。
- 不是给某一家店定制的人设工程。不设虚构品牌、不扮演「某公司 AI 老大」——那是面试时可选的口述角度，不是产品身份。
- 不是八个可以拆开投不同岗位的玩具仓库，也不是七个一样厚的产品线。拆开之后，面试官会问数据从哪来、新系统怎么一天接上、RAG 撞墙之后怎么办——答不上来就是 demo。
- 不是传统数仓/指标平台的缩小版。这里的中台服务的是 Agent：要检索、要引用、要给 MCP 当工具，而不是只出报表。
- 不是把 LangChain / LangGraph / RAG / Agent / 微调名词堆进 README。每条主线主张必须能对着代码、测试或评测报告讲清楚。不训练模型。
- 不是 Sierra / Gorgias / Decagon 的开源竞品。没有坐席队列、没有店铺自动同步、没有真 OMS。定位是**治理语义的可运行说明书**，外加一条受约束的 Agent 循环。
- 不是给面试官准备的点击演示。面试不投影控制台、不走 3 分钟点穿；「完善」不是冷启动好看，是死亡问能钉到文件。
- 不是「形状 7/7 就停」。有入口、有口述稿，只证明能讲个形状；没有评测数字、没有 Agent 循环、治理路径在真实商品上走不通，口头也会被拆穿。

## 2. 解决什么问题

对象是**有商品、客服、运营、直播、销售团队的电商业务**（店铺、品牌站、代运营都算），不是某一家店。典型数据散落在 IM、网盘、表格里。这套体系要通用地接住这些事：

1. 客户问商品特点、规格、售后口径时，AI 客服按中台已发布知识回答；没证据就拒答并留下缺口，而不是编造或靠值班同事背话术。
2. 客服答不上来时，记下知识缺口，人补资产并发布，同一问法下次能答——知识变好靠发布，不靠训练模型。
3. 运营要投放文案时，走可观察的编排（读商品 → 生成 → 引用已发布素材 → 人确认投放）；素材经质检才进中台，不是聊天窗口里「帮我做张图」。
4. 直播片段经人拣选登记为资产，进中台后可检索、可被引用，而不是留在本地文件夹。
5. 销售上岗用真实客户对话场景抽题打分，而不是念 PPT。同一份聊天资产既喂客服 RAG，也喂考核。
6. 以上任何一块要接新系统时，走的是「中台已发布数据 → MCP/提示词 → 系统」，而不是「再挖一张库、再开一个月需求」。连接层不能发布。

这六件事必须共享同一份被治理过的数据。这就是中台作为核心的理由。类目、店铺名、商品样例都是可替换的种子，不写进产品身份。

深度不均是产品决策，不是偷工：1、2、6 必须厚到经得起 grill；3、4、5 必须真实（流水线不假、能指到资产 ID），允许成本降级（无图生、无 ASR、无扮客多轮、无投放日历）。

## 3. 体系怎么咬合

七块能力全部在一个仓库里。它们共用一份数据契约，不是七个产品线。

```
  上传 / MCP登记 / 种子          库存·订单（工具，不进索引）
  会话回流 / 切片拣选 / 素材成品
                 │
                 ▼
        ┌─────────────────────────┐
        │  ④ 数据中台（核心）        │
        │  登记 → 机洗 → 人洗 → 发布 │
        │  来源 · 血缘 · 检索索引     │
        │  知识缺口（拒答排队，人补）  │
        │  评测只读已发布（不是资产）  │
        └────────────┬────────────┘
                     │
     中台接口（内部） / MCP 连接层⑦（仅外部 Agent）
                     │
     ┌───────────┼───────────┐
     ▼           ▼           ▼
   ① 客服Agent  ⑥ 考核抽题   ② 运营编排
     │                         │
     │ 拒答→缺口→再治理         │ 读 ⑤ 已发布素材
     └──────── 回流 ───────────┘        ▲
                                        │ 切片汇入
                                 ③ 直播切片
```

读图规则：

- **加厚主线**是 ①④⑦：接待（bounded loop + 拒答 + 缺口）↔ 中台权威 ↔ 外部 Agent 经 MCP 读同一指针。
- **契约证人**是 ②③⑤⑥：证明同一 `A-xxxx·vN` 能被素材、切片、考核、运营引用；不加厚成内容工作室或上岗系统。
- **数据中台**是核心枢纽：所有输入经过治理，所有输出可被下一系统引用。只有已发布进检索。
- **MCP** 不是第七个业务，也不是模块总线。内部 ①②③⑤⑥ 走中台接口；MCP 只给外部 Agent 发现和调用同一套接口。没有 publish。
- **客服是 Agent，运营不是。** 客服：模型可提议工具，代码授权，有步数上限和可回放轨迹。运营：写死的可观察步骤 + 失败续跑 + 人确认投放（投放 ≠ 发布）。
- **数据可替换**：种子目录里的店铺/商品可整包替换；系统不依赖任何一个品牌名。治理路径（规格写回、必填闸门、发布进索引）必须在这批真实商品上走得通——为了能讲，不是为了冷启动点穿。
- **推理**：客服走厂商 Chat API。图上没有微调箱。
- **评测**：golden 集只读已发布，不是中台对象，用来量检索/拒答/工具轨迹。没有数字不许说 RAG 质量。

## 4. 七块能力各自必须证明什么

编号按业务发生顺序，不是开发顺序。每块都必须能指出从中台读了什么、写回了什么，证据在代码和测试里，不靠现场点一遍。主线（①④⑦）的「必须有」按面试级写；证人（②③⑤⑥）按「契约真实、允许薄」写。

### ① AI 客服（主线）

- **业务**：客户咨询（商品卖点、规格、售后口径、订单/库存）先由 AI 接待。
- **在体系中的位置**：中台知识的第一个消费者；对话日志是中台最重要的回流。这是仓库里唯一必须是 Agent 的路径。
- **必须有**：
  - 只检索当前已发布；引用是服务端定的 `{asset_id, version_no}`，模型没有引用决定权。
  - 无证据不调模型：拒答 + 转人工 + 知识缺口；工具失败转人工不建缺口、不拿检索顶。
  - **bounded loop**：模型可提议工具（订单/库存/检索），代码做资格校验；`max_steps` 有上限；轨迹可回放、可进评测。不是 if 链冒充 Agent，也不是无限 ReAct。
  - 多轮记忆不制造证据；工具轮可再触发，不能靠记忆编造。
  - 检索可测：有四分布 golden（正例 / 同义改写 / 跨商品混淆 / 应拒答）和报告数字。默认词法（CJK bigram）是刻意基线，增强必须 before/after 同一报告才许留。
  - 生成有忠实度约束：命中切块覆盖不够则回退或拒答，不把幻觉当 answer。
  - 订单/库存是工具数据源，mock 到契约可测；写操作若有，必须两阶段（资格查询 → 人确认 → 执行），资格在代码。
- **面试要能讲**：loop 在哪、工具谁授权、检索从哪来、为什么不把商品页塞进提示词、保修/质保怎么测过、答错怎么追到 `A-xxxx·vN`。

### ④ 数据中台（核心，主线）

- **业务**：文本、图片、视频、聊天记录进入后，经过机器清洗 + 人工清洗 + 人工补充，变成可被 Agent 使用的资产。
- **在体系中的位置**：唯一的数据权威。知识库不是中台的别名；知识库是中台对外的一种视图。中台也是 Agent 的长期记忆：对话回流 → QA 草稿 → 人洗 → 已发布切块。
- **必须有**：
  - 资产登记（必须带字节）、三态、版本指针、血缘（从哪来、被谁引用/写回/导出/考核用过）、检索索引（发布事务内切块）、导出、知识缺口。
  - 发布权只在治理台；连接层不能发布。第一版不做自动发布。
  - 可替换种子包：`data/seed/`（或一键灌入），带真实 `spec_schema` 的商品 + 已发布规格/政策，让写回/闸门/检索在非玩具目录上成立。不是为了面试点屏幕。
  - 缺口关闭必须可验证：发布后同一问法能命中；重复缺口有热度（或等价仪表）。关缺口不是只改 FK。
  - 多来源走同一闸门（上传 / 回流 / 切片 / 素材 / MCP 登记 / 种子）；许可与出处可指。
- **面试要能讲**：没有中台为什么接新系统要一个月；有了中台为什么「提示词 + MCP」一天能出**读同一权威**的系统。这句话必须能对着仓库里的接口讲，不能只写在 README。

### ⑦ MCP 与 Agent 实战（连接层，主线）

- **业务**：把中台能力暴露成工具，让外部 Agent（Cursor / Claude / 第九系统）用同一套协议接入。
- **在体系中的位置**：贯穿层，不是独立业务。内部模块不经 MCP 互调。
- **必须有**：
  - 检索已发布、取已发布正文（含历史已发布版）、登记回流（必须带正文，来源服务端定）、导出已发布。没有 publish。
  - 活状态只读工具（商品/库存/订单）包的是与客服同一套函数，仍无写权威、仍无 publish。
  - 独立 Bearer，空密钥拒绝，不复用操作者 cookie。
  - **协议证据**：独立客户端脚本 + 测试钉死固定剧本——search → get → register；publish 不存在；未发布 search 空。不要求面试现场连 Cursor。Connect 页若不是真 MCP，口述必须主动说它是等价查询。
  - 导出是数据包，不是微调集。
- **面试要能讲**：新系统 = 提示词 + 选哪些 MCP 工具；内部为什么不走 MCP；为什么「一天接上」接的是读权威，不是改权威。对比传统「新库 + 新接口 + 新联调」。

### ⑤ AI 素材中心（契约证人）

- **业务**：按商品生成可复用的投放文案，质检通过后登记为资产进中台。
- **必须有**：任务、质检（规则 + 人抽检）、失败不进中台、回写为 `kind=material` 资产。流水线不能假。
- **允许薄**：宣传图、短视频成片按成本不做；可明示降级。不把「帮我做张图」的聊天窗口当素材中心。
- **面试要能讲**：素材是可引用的中台资产，不是生成器输出文件。

### ② 运营编排（契约证人）

- **业务**：运营人员驱动「读商品卖点 → 生成投放文案 → 引用已发布素材 → 人确认投放」。
- **必须有**：可观察的步骤轨迹、失败从断点续跑、人工确认后再投放。投放是渠道动作，不等于治理台发布。
- **允许薄**：不必自然语言 planner，不必真调素材中心任务，不必投放日历，投放可 mock。
- **面试要能讲**：长链路断了怎么办（轨迹 + 重试 + 人确认）。不要把它说成多 Agent 编排。

### ③ 直播切片（契约证人）

- **业务**：直播片段经人拣选，登记为视频资产进中台，可被检索和引用。
- **必须有**：候选（时间码 + 转写 + 商品标签）→ 拣选 → 登记 → 治理发布 → 客服能引转写。候选不是资产。
- **允许薄**：v1 字节可以是带时间码的转写文本（ADR 0039）；不做 ffmpeg/ASR，不承诺「15 分钟出 20+ 条自动切」。
- **面试要能讲**：切片为什么要进中台（可检索、可复用、可被引用），而不是留在本地文件夹。

### ⑥ AI 销售考核（契约证人）

- **业务**：从已发布对话抽场景，训练销售并按维度打分，留下可回放记录。
- **必须有**：题源锚 `A-xxxx·vN`；按维打分；记录不是中台对象（打的是人，不是客服引擎）。
- **允许薄**：单轮；题面即开场，模型负责评分，不扮演顾客追问。
- **面试要能讲**：同一份聊天数据如何服务两个系统（客服学习 + 销售考核）。不要说「AI 扮演顾客」除非真做了。

## 5. 讲故事只用这三条

1. **接待闭环**：客服 bounded loop 只引已发布 → 无证据拒答并留下知识缺口 → 人补资产并发布 → 同一问法下次能答；整段会话可回流再治理。答错追 `A-xxxx·vN`。检索质量用评测报告说话。
2. **内容闭环**（证人，允许薄）：商品知识 → 素材中心生成并质检入库 → 直播切片拣选汇入 → 运营编排分发（投放 ≠ 发布）→ 成品再进中台。不要把这条讲成自动剪辑厂或图生工厂。
3. **连接层**：外部 Agent 经 MCP 检索/取/登记同一份已发布权威；没有 publish；未发布搜不到。这就是「一天接新系统」——接的是读权威，不是改权威。

面试 30 分钟只讲这三条，对着代码和报告答追问。知识变好靠发布，不靠训练。不必编一个公司人设。七块不要巡游。不现场演示。

## 6. 完成标准

分两段。形状已经达成；当前未完成的是面试级。

### 6.1 形状（已达成，第 27 刀；2026-09-06 原文存档）

1. **一个仓库、一套可替换的种子数据、一个可运行的控制台**，七块能力都有入口，而不是七份 README。
2. **中台是唯一数据权威**：客服、考核、素材、切片的演示数据都能指出中台资产 ID；禁止各模块私藏一份互不同步的 JSON。
3. **MCP 可被至少一种外部客户端连上**，工具列表能被模型选中；本仓库自己的 Agent 走中台接口，不经 MCP。
4. **每条业务路径可演示**（人能点、或脚本能跑），并且能回答「数据从哪来、写到哪去」。
5. **简历只写一个主项目名称**，模块作为职责展开；README 提供 3 分钟口述稿（接待含缺口、内容、MCP、中台为什么是核心）。口述可以带业务例子，但不绑定虚构品牌。
6. **死亡三问有代码对应**：编排可见、失败可重试或可转人工、检索无命中时拒答而不是幻觉。
7. **产品表面没有虚构公司名**。种子数据若需要店名，放在 `data/seed/`，可整包替换。

### 6.2 面试级（当前目标）

> 签核：本节由施工会话起草（2026-09-09），Owner 同日逐条评估**采纳**（评估记录见当次会话）；两处修订生效——§6.1 恢复达成时原文存档，§8 禁词「AI 扮演顾客」限定为「把单轮评分说成顾客对练」。

仓库作为「完善成体系、能写进简历、经得起 grill 的 Agent 项目」完成，当且仅当下面全部为真。**证据在代码、测试、评测报告里**——面试不演示，但问到必须能指出文件、函数、数字。文档里写了、仓库对不上，不算。

1. **数据契约在生产级目录上成立。** 不是 2 个 SKU、也不是 91 个空 schema 名字。可替换种子 + 公开主数据（Open Food Facts 条码/品牌/净含量，ODbL；Wikidata 制造商/质量等属性，CC0）灌进 `products` 与规格文档；写回、必填闸门、发布进索引有测试。评论能挂则挂商品。许可可指。空名字目录不算完成。详见 `docs/research/production-grade-catalog.md`。
2. **评测有数字。** golden 四分布（正例 / 同义改写 / 跨商品混淆 / 应拒答）；检索 recall@k + 拒答率写进 `docs/research/rag-eval-report.md`。没有这份报告，简历不许写 RAG 质量。检索增强必须 before/after 同一报告才许留。
3. **客服是 bounded Agent。** 模型可提议工具，代码授权；有步数上限；轨迹可回放、可断言。无证据不调生成。citations 服务端定。越狱改不了工具资格。不是 if 链，不是第二套框架。
4. **检索口径诚实。** 默认是封闭域词法（CJK bigram，与 Lucene CJK analyzer 同构）；pgvector 镜像未用就不写进技能栏。上向量/rerank 的唯一门票是评测报告里词法+同义词仍不够。
5. **MCP 协议有自动化证据。** 独立客户端脚本 + 测试走完 search → get → register；工具列表里没有 publish；未发布 search 空。活状态只读工具与客服同一函数。不要求面试现场连外部 IDE。
6. **飞轮可指。** 缺口关闭后同一问法能命中（关闭 ≠ 只改 FK），有测试。重复缺口有热度或等价仪表。血缘能从一条错误回答追到当时的资产版本。
7. **简历与代码对齐。** 一个主项目名称，模块当职责展开，不并列成七个产品。口述不出现对不上的词：七个 Agent、pgvector RAG、15 分钟自动切 20 条、把单轮评分说成顾客对练（「AI 扮演顾客」）、一天接任意业务系统、自进化无人化。
8. **死亡问有代码。** loop 在哪、工具谁授权、答错追哪一版、保修/质保怎么测、新系统为什么不能经 MCP 发布、长链路断了怎么续。

未完成：形状 7/7 但评测 13 条空 key、客服仍是正则分派、91 个商品空 schema 讲不出写回、目录没有条码/品牌/净含量真值、MCP 只有冒烟、简历把证人模块写成生产 Agent。

施工刀序见 `docs/roadmap.md`（数据 II 收口 → 数据契约 → CI → 评测尺 → 同义词 → 客服真 loop → MCP → 飞轮仪表 → 忠实度/反馈/两阶段写）。

## 7. 明确不做

- 不接真实淘宝/抖音商家后台（用可替换的种子业务数据演示；公开数据集须注明许可）。
- 不把产品做成「某某优选 AI 部门」；界面、仓库、简历主标题都用通用名。
- 不自研基础大模型；不训练、不接厂商 Fine-tune 作业、不在客服里切微调底座。推理只走厂商 Chat API（ADR 0028）。
- 不做完整数据仓库主题域、不写实时数仓论文。
- 不为了凑技术名词引入第二套 Agent 框架（LangGraph / 多 Agent 互调 / A2A / 技能市场）。客服循环写在本仓库 services 里。
- 不把各块做成多个部署单元才算「像大厂」；先保证同仓可跑、契约清晰，再谈拆服务。
- 不做 RBAC、多租户、真坐席队列——单店单操作者是 v1 决策（ADR 0008/0016），不是没做完。
- 不加厚证人模块：图片生成、投放日历、真 ASR/ffmpeg、考核扮客多轮、运营改 planner。
- 不先接 pgvector / embedding「再说」。没有评测尺就是随机加依赖。
- 不把 Connect 页假装成 MCP 协议。
- 不为面试点屏幕做演示工程：冷启动表演、3 分钟点击脚本、Connect 页演戏，都不是完成标准。测试、评测报告、独立脚本才是答辩证据。

## 8. 简历怎么用这套东西

主项目名称建议（可改，含义不能改）：

> 电商 AI Agent 体系（数据中台 + MCP 连接层）

展开时按业务职责写，不按框架写，也不按虚构公司写。**不要写成七个产品：**

- 负责数据中台：多模态资产治理、版本化发布、血缘、知识缺口飞轮；只有已发布能被 Agent 引用
- 负责 AI 客服：bounded Agent（模型提议工具、代码授权）+ 中台 RAG（版本化引用、无证据拒答）+ 评测数字
- 负责连接层：MCP 把同一份已发布权威暴露给外部 Agent，没有 publish
- 素材 / 切片 / 考核 / 运营编排：同一契约的消费方（一笔带过，证明资产 ID 能跨模块用）

技术栈写在职责后面，绑定结果，不单独开「技能清单」糊弄 HR。pgvector、LangGraph、微调这类词，代码没用就不写。

## 9. 词必须统一

| 用这个 | 不要用这个 | 为什么 |
| --- | --- | --- |
| 电商 Agent 体系 | 中台主线、八个 demo、某某公司 AI 部门、七个 Agent | 体系是通用产品；只有客服是 Agent，其余是契约证人 |
| 受约束的 Agent / bounded loop | ReAct 无限循环、多 Agent 编排、LangGraph | 模型提议，代码授权；有步数上限；无第二套框架 |
| 数据中台 | 知识库（当整体）、数据湖、数仓 | 知识库只是中台的一种视图 |
| 资产 | 文件、语料、素材（当中台对象时） | 中台里登记的是资产，素材是业务成品 |
| 连接层 / MCP | 第八个业务系统、模块总线 | MCP 只对外，不与客服并列抢戏 |
| 一天接新系统（读权威） | 一天接任意业务系统、MCP 能发布 | 接的是已发布指针，改权威仍要人 |
| 回流 | 保存、导出一份副本 | 强调写回中台、可被下一系统引用 |
| 厂商模型 / 推理 API | 我们的大模型、微调底座 | 只调用厂商 Chat API，不训练 |
| 种子数据 / 店铺 | 产品名、品牌人设 | 店名只存在数据层，可整包替换 |
| 词法检索 / CJK bigram | pgvector RAG、向量检索（未用时） | 默认工程选型；镜像未用就不说 |
| 评测报告 | RAGAS 已上、Eval-driven（无数字时） | 没有报告不许写 RAG 质量 |
| 契约证人 | 七个产品线、内容工作室、上岗系统 | ②③⑤⑥ 证明契约，不加厚 |
| 形状完成 | 项目已完成、生产级 | 形状 7/7 已达成；面试级才是当前完成定义 |
| 答辩证据（测试/报告/脚本） | 面试演示、冷启动点穿、3 分钟点击 | 面试不演示；完善度不靠屏幕 |

垂直域是**电商**（客服、直播、素材、销售都绑在这条链上）。通用指的是不绑死某一家店，不是做成行业无关的空壳平台。完善指的是**主线经得起 grill、证人契约真实**，不是七块都做成生产系统。
