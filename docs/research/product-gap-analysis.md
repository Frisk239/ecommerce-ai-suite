# 产品视角全面差距分析（用户走查 × 竞品对标 × 内部盘点）

日期：2026-09-10。方法：三路并行——真实用户旅程走查（API 实测+读码取证）/ 开源竞品对标（Onyx、RAGFlow、Chatwoot、Dify、Langfuse 等）/ 内部实现缺口盘点（12 项逐查）。工程面收官状态见 goal §6.2 终态对账（`docs/progress/fidelity-feedback-closeout.md`）；本文回答「作为**产品**还差什么」。

---

## 一、最痛三件事（用户走查实证，跨视角同根）

### 1. 商品是空壳：无法创建、无价格、顾客问「卖什么/多少钱」全部拒答

这是三条走查线索汇聚的**第一大产品缺口**：

- **操作者无法上架商品**[阻断]：全 API 无 `POST/PATCH /api/products`（`routes/products.py` 纯读 63 行），UI 纯只读，空态文案「商品由中台维护」是误导——中台也没有入口。想上架只能改种子代码。
- **91 个 Wikidata 商品是名字壳**：spec_schema/spec_values 全空、库存是固定种子随机数，8 个类目中 6 类规格模板为空——「数据契约核心」的口号下，契约的大部分格子没有内容。
- **顾客第一问即被拒**[痛点]：实测「你们卖什么」→ refusal+转人工（114 个在库商品不作为知识源）；「那个多少钱」→ refusal，且**全类目 spec_schema 无价格字段**——价格类问题永远无法闭环，只会不断产生补不上的缺口（实测已生成 product=null 的价格缺口，「去补文档」是死路，因为文档也没有价格字段可写回）。
- **下拉 114 选 1**[痛点]：登记/素材/编排三处商品下拉全量列出（93 空壳+中英文混杂），无搜索无过滤。

**根因**：商品体系停留在「种子只读道具」，没有升格为可运营的对象。**最小补法**：products 加 POST/PATCH 端点+商品页编辑表单（规格按模板逐项填）；spec_schema 增加价格类字段（价格/库存价）；商品目录页生成一份「在售清单」文档资产自动登记（让「你们卖什么」可答）。

### 2. 顾客转人工是死路

- 拒答文案「已转人工」之后**没有任何后续预期**（谁/何时/怎么联系），也没有留联系方式的通道。
- 实测显式说「转人工吧，联系我138…」被当成知识问题走检索→「证据未覆盖」——**转人工意图本身不识别**（只挂在拒答/工具失败两条自动路径上）。
- 词条自认「v1 只是消息种类，没有坐席队列」——但顾客侧连「留个电话/工单号」的最小闭环都没有，被困在对话里。

**最小补法**：意图识别加「转人工」触发（词表+模型提议双路径）；转人工消息带「留下联系方式」输入；操作者侧转人工会话置顶（哪怕只是列表过滤+角标）。这与竞品 Chatwoot 的收件箱方向一致但可以远小于它。

### 3. 操作者是聋子：零通知、零仪表

- **零通知**[痛点]：缺口从 5 涨到 7、素材待抽检、顾客点了「没有帮助」——操作者不打开对应页面就永远不知道（全仓无轮询/角标/推送）。
- **客服表现无仪表**[痛点]：全部统计=总览 5 张计数卡；无会话量趋势、无拒答率趋势、无缺口趋势、无负反馈汇总。「我的客服干得怎么样」这个商家最基本的问题回答不了。
- 评测集（96 条）只能脚本跑，产品内不可见。

**最小补法**：侧栏角标（open 缺口数/待抽检数，页面加载时带出）；总览页加一张「近 7 日会话/拒答/缺口」迷你趋势（后端一个聚合端点即可）。

## 二、内部实现分级盘点（12 项）

| # | 领域 | 评级 | 现状证据 |
|---|---|---|---|
| 1 | 商品体系 | 单薄 | 91 Wikidata 空壳+无写端点；spec/stock 假 |
| 2 | 库存 | **纸糊** | 种子固定值永不变化；无同步/对账 |
| 3 | 订单 | **纸糊** | 3 条种子单无 CRUD；确认退货后 order.status 纹丝不动（只追加 events）——追问一句就穿帮 |
| 4 | 直播切片 | **纸糊** | 无视频/ASR；候选=改了名的时间码文本（WANDS 英文查询合成）；「15 分钟切 20 片」故事无实现 |
| 5 | 素材中心 | 单薄 | 只有文案（图/短视频脚本零实现）；质检 4 条硬编码；打回无理由输入 |
| 6 | 销售考核 | 单薄 | 题库=已发布对话 QA（实测 6 题 4 英文）；单轮无追问；冷启动 0 题 |
| 7 | 运营编排 | 单薄 | 三步固定流水线；「自然语言驱动」实为选商品点按钮；投放后无任何后续 |
| 8 | 顾客通道 | 纸糊偏单薄 | 无嵌入 widget（11 个参考仓未用）；**令牌原文存库无 TTL 永不过期**（操作者 cookie 反而有）；满意度只收负评 |
| 9 | 多轮记忆 | 单薄 | N=4 写死；无跨会话/顾客画像 |
| 10 | 权限/多租户 | 单薄 | 单操作者无角色；「换店=整包替换」实际要手跑四个脚本 |
| 11 | 可观测 | **纸糊** | 零 metrics/结构化日志/trace 面板；线上排障只有 logger+audit+血缘 |
| 12 | 部署 | 纸糊偏单薄 | compose 开发形态（web 是 vite dev）；README 无生产部署章节；无 HTTPS/备份 |

「纸糊」= 演示都撑不起追问；「单薄」= 能演示但一追问就穿。**最伤叙事前五**：直播切片（故事与实现差距最大）、顾客通道（令牌永不过期是安全隐患+无载体）、商品体系、订单退货状态、可观测。

## 三、竞品对标（我们 vs 优秀开源）

**我们的独有优势**（对标中确认，应继续放大）：可追溯知识治理闭环（三态+发布才进索引+引用锚定 A-xxxx·vN+血缘+缺口验证闸）——Onyx/RAGFlow 是「索引即知识」，做不到逐引用版本回放；拒答留缺口的负样本队列是 Langfuse 也没有的领域特有形态。

**差距与最值得抄的**：

| 竞品 | 它有什么我们没有 | 最值得抄的一个 |
|---|---|---|
| [Onyx](https://github.com/onyx-dot-app/onyx) / [RAGFlow](https://github.com/infiniflow/ragflow) | 40+ 开箱连接器（Drive/Notion/飞书）+自动同步；深度文档解析（PDF 表格/扫描件） | 连接器框架+定时拉取→待人洗队列（对接我们的治理闸天然咬合） |
| [Chatwoot](https://github.com/chatwoot/chatwoot) | 多渠道收件箱/团队协作/SLA/CSAT 调查 | 会话结束 CSAT 1-5 星（挂到会话与缺口分析）——我们已有 thumbs-down，补全很近 |
| [Vercel AI SDK](https://github.com/vercel/ai) 生态 | Generative UI（对话内商品卡/加购组件） | SSE complete 携带结构化商品数据→前端渲染商品卡（与价格字段补齐联动） |
| [LangGraph time-travel](https://docs.langchain.com/oss/javascript/langgraph/use-time-travel) / Dify | checkpoint 式回放（任一步看状态/改输入重跑）；内置日志/反馈/标注面板 | 运营编排每步存快照支持「从第 N 步重跑」（我们轨迹已落库，差快照与 UI） |
| [Langfuse](https://langfuse.com/docs/evaluation/evaluation-methods/annotation-queues) / Phoenix | 分层 trace 树/成本延迟面板/**人工标注队列**/失败 trace 一键转评测集 | Annotation Queue——拒答轮/抽查轮进队列打分，与缺口/评测回流打通（我们是天然素材） |

## 四、建议排期（产品价值 × 实现量级；供裁决，不锁）

**第一梯队（补最痛，全小-中量级）**
1. **商品 CRUD + 价格字段 + 目录可答**——解开 A2/B2/B4 三处同根断裂（中）
2. **转人工意图识别 + 留联系方式 + 操作者置顶**——顾客不再被困（小-中）
3. **侧栏角标 + 近 7 日趋势聚合**——操作者不再聋（小）
4. **退货确认迁移订单状态**——一句追问不穿帮（小）

**第二梯队（把纸糊变单薄）**
5. 顾客令牌 TTL+过期校验 + 单文件 embed.js（小）
6. 直播切片接一条真链路：真 mp4 + ffmpeg 按时间码切出真实片段文件登记（中）
7. /metrics + 结构化日志最小版（小）
8. CSAT 1-5 星补全反馈闭环（小）

**第三梯队（对标增强，按需）**
9. 会话 trace 落库+回放面板 / 标注队列（中-大）
10. Generative UI 商品卡（中）
11. 知识源连接器·飞书/企微（大）
12. 收件箱+坐席协作 / checkpoint 编排重放（大）
