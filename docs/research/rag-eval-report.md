### 分层解读：10.0% 不是幻觉率，是「严格原文对照」下的组装框架语越界率

这个数字必须按构成读，不能当幻觉率引用：

- **评测尺评的是模板路径**。`run_eval` 直调 `compose_answer`（无 LLM key 的证据组装
  模板），回答由构造保证是命中块的摘录组装（0018 无证据不调模型的同一纪律）；评测尺
  刻意不跑 LLM 生成路径（可复现性设计，35 刀 spec）。模板路径没有幻觉面。
- **judge 协议是逐句严格原文对照**（「每条陈述必须在证据里有原文依据……任一陈述找
  不到原文依据 => false」）。模板回答每句都带框架语——「根据已发布的规格文档《资料
  名》，品牌为 X」：事实体「品牌为 X」在 chunk 里有原文（「品牌：X」），**框架语不在**。
  第 81 刀特意加进回答的资料名（供模型核验实体归属）恰恰是 chunk 文本里没有的部分。
- **对照实验（根因实锤）**：同一问题同一证据，原模板回答（带框架语）judge=False；
  剥掉框架语只留事实体「品牌为1MD Nutrition。」judge=True。低数字的成因是协议 ×
  形态错配，不是编造。
- **判 supported 的 8 条全部是对话（dialogue）资产的回答**（第二遍全量逐条 verdict
  定性：pos-002/017/025/037、syn-007/016/017、conf-002）——模板对 dialogue 的组装是
  **chunk 原文逐字粘贴**（「顾客：…/答：…」轮次行原样进回答），与证据逐字贴近故判过；
  document 类组装是字段改写（「品牌为 X」← 证据「品牌：X」）+ 框架语带书名号资料名，
  措辞变换即被严格协议判不过。**该列实际度量的是「回答措辞与证据原文的逐字贴近度」，
  且判分面按资产种类二分**（dialogue 贴近、document 有改写）——组间差异（paraphrase
  12.0% / confusion 6.7% / positive 10.0%）是三组期望资产里 dialogue 占比不同的投影，
  不是检索或生成质量差异。
- **两遍复跑聚合逐位一致**（第一遍 run_eval `--judge`、第二遍独立脚本逐条
  `judge_with_retry`，均 8/80 supported、80/80 评上、零失败条目）——当日同网关口径下
  判定稳定；跨日/跨网关的漂移边界未测，引用数字时应带跑全日期。

### 该列的定位订正（本刀结论）

faithfulness judge 列度量的是「回答措辞超出证据原文的程度」（严格原文对照口径），
**不是幻觉率**。真幻觉面在 LLM 生成路径上，由线上机制守：覆盖声明闸按句摘除/收口
（58/69/81 刀）、`chat_fallbacks_total{reason=coverage|no_coverage}` 指标（63/82 刀）、
引擎金标 `golden_engine.json` 进 CI（68 刀）——那条路径的 judge 化评测（对 run_ask 的
生成输出评忠实度）受 LLM 输出非确定性约束，不进本可复现评测尺，属后续观察项。goal
§6.2「评测 faithfulness judge 列待网关补跑」以**已跑全 + 定位订正**收官。

  路径无模板框架语，系统提示的逐句引用约束（[1][2]）让 156/226 的陈述可
  溯源到块原文——**同一协议下 10.0% → 69.0%**，翻转主要来自形态差。
- **幻觉面真出现了，但是小头**：16/226（7.1%）矛盾/编造型，其中最大同型簇
  是「材质为钛钢」×6——模型拿标题词冒充字段值，与引用源显式字段直接矛盾，
  是教科书式幻觉；泛化（换货评论→退货规则）与实体错配（配料当品牌）各零星。
  其余 54 条 False 的大头不是编造：32 条是「模型看不见引用源全量就诚实说
  未覆盖」（证据窗 top-2 太窄的代价，与 #90-P1 债 2 品牌块排序同根因）、
  22 条是「值对但归属依据是 prompt 标题标签」——后者正是 87 刀框架语越界的
  **生成镜像**（框架语→归属语，judge 证据面无标题的口径差）。
- **新问 8/10（80.0%）高于存量 68.5%**：新问全走当前引擎（81 刀标题进
  prompt + 58/69/82 刀三道闸后的行为），存量含历史引擎输出；两条新问 False
  同属覆盖否认/归属（材质/上市年份在引用源里、模型证据窗没看到或没认）。
- **口径边界**：87 刀证据=检索 top-3 块（judge 与模板同窗），本刀证据=引用
  版本全量切块（比模型实际可见的 top-2 **更宽**——判的是「答案 vs 引用源」
  忠实度，不是「答案 vs prompt 窗口」）。两个数字都不可当幻觉率引用。

### 挖掘方法（scripts/eval/dig_oov_synonyms.py，新增）

输入=真实问法池（collect_questions 101 清单 210 问 + 本刀重跑 104 清单 215 问，合并去重）
+ golden oov_syn 15 条探针（探针词也是真实缺口证据）。**分词假设检验**：问句按停用字/
非中文字符切段、段内 2-4 字滑窗为候选 token；目标词表三层（表内词全 35 / 语料字段名 25 /
语料滑窗词 df≥2 共 1714——新组发现如 雕字→刻字 只能从语料侧找目标）；对每个
(token→目标词) 假设，把「token 轮转到目标词」的试探边临时插进 synonyms 规则表
（`hypothesis_rules` 上下文管理器——retrieve 在调用点读 apply_synonyms 的模块全局，patch
即**实跑语义**），retrieve 前后对照：探针按期望锚 recall 翻转判收、池按零命中→命中判收；

真目标反而被截断——实测教训）。词频分拣：池频次 ≥2 或探针在场 → priority（113 token），
频次 1 非探针 → deferred（336，记候选不收）。清单工件
`scripts/eval/out/oov-syn-candidates-104.json`（449 token：token+频次+来源问句+替换假设
（归一到表内哪个词/哪个语料词）+当前/假设命中对照）。--ab 模式=轻量对照（oov_syn 15 +
