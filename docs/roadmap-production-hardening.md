# 生产数据验收硬化 roadmap（2026-09-19 立项）

日期：2026-09-19。来源：生产级数据重灌（第 123 刀，`scripts/reseed_production.py`）后的七站重验收——Owner 裁决「针对刚刚查找到的所有问题（含上一站的）落优化路线；缺真实直播素材用 agent-reach 调研抓取实测；洗帧 bug 修复+健壮性增强；审计全系统同类健壮性不足」。状态：**Owner 立项，施工权威**。

## 北极星

**生产数据上每一份「已发布」都真相自洽（文案=画面=归属），失败必有声，直播线有真实素材可演。**三条验收线：

1. **真相自洽**：切片资产的转写、切出的帧、所挂商品三者一致——「引用=证据」红线延伸到视频面（本轮实证破裂：A-26/27/28 文案说保温杯、画面是显示器）。
2. **失败必有声**：脚本/服务的关键步骤静默跳过=验收盲区（本轮实证：reseed 洗帧步因商品匹配失败无声跳过、对话步骤参数错静默「完成」）。
3. **直播线真实**：至少一路真实直播形态的长视频（带语音、可 ASR、有讲解节奏）过 上传→转写→拣选→真切→发布→洗帧→客服引用 全链。

## 第 124 刀：切片真相链修根（错绑+盲选+静默跳过+污染数据修复）

**内容**：

1. **错绑修根（服务面）**：`register_recording` 的顺手默认动作收窄——只绑 `source_video_label == 录像 label` 的未绑定 pending 候选（演示流：同名批次照旧自动绑；跨源候选不再被劫持）。显式改绑端点（49 刀）不动。
2. **盲选修根（脚本面）**：reseed step_dell 只从**本次上传录像自己的候选**里拣选（按 recording_id 过滤），且打印每条拣选的候选 id+转写头；洗帧步商品匹配改按类目（`category == "显示器"`），匹配失败显式打日志+非零提示，不再无声跳过。
3. **污染数据修复**：A-26/27/28 按 ADR 0042 废弃语义处置（不删行），从真实 Dell ASR 候选（英文转写）重新拣选注册+发布；客服检索面验证新切片可被引用、旧切片已出榜。

**验收**：错绑修根有单测钉（同名绑/异名不绑）；重跑 step_dell 全程日志无静默段；A-26/27/28 出检索榜、新切片的洗帧 VLM 评注与转写一致（画面=显示器、文案=monitor）。

## 第 125 刀：真实直播素材调研与抓取（agent-reach）

**内容**：`docs/research/live-stream-sources.md`——公开许可的直播/长视频形态素材源调研（候选：Internet Archive 直播录像/Government live 流存档/Wikimedia Commons 视频/CC-BY 讲解长视频/公开数据集如 TVNewsarchive；**不爬 B 站/抖音/Twitch 回放——版权+ToS 灰色**，89 刀先例）。要求：带语音（可 ASR）、≥10 分钟（有讲解节奏）、许可可商用或至少可演示。抓 1–2 路真实素材：上传源录像→云 ASR 转写→拣选 3–5 条→真切发布→洗帧→客服问句引用切片，全链在生产库实测。

**验收**：调研文档每项带链接与许可证据；抓取素材过全链的实测记录（转写条数/切出时长/洗帧帧数/引用命中问句）。

## 第 126 刀：健壮性审计（静默失败同族三路）

**内容**：针对第 6 项实证的「静默跳过」族，三路只读审计：
- **脚本面**：`scripts/` 下所有写入链步骤逐个过——异常吞掉、条件跳过无日志、盲序取值（`[:N]`）、失败后仍打 ✓ 的形态；
- **服务面**：`services/` 里 `except: logger` 后继续走（错误降级是否有用户可见面）、条件写路径无 else、0 行更新无观测；
- **端到端面**：故意制造失败（坏文件/无网/缺 key）重跑重灌链，比对「日志声明的完成」与「库里真发生的事」。

**验收**：P0/P1 全实修或入路线；审计报告落 `docs/progress/`，测试数不降。
