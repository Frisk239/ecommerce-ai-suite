## 问题（审计实测）

`保温杯刻字怎么收费？`（该问句有 5 条弱命中）→ 忠实度闸不触发（命中>1）→ 模型生成「当前已发布证据未覆盖刻字收费信息。」→ 落库 `kind=answer`、**citations=[13,9]**、`handoff=false`、**不落缺口**：
- 顾客看到「未覆盖」却挂着两个引用芯片；
- 治理台收不到这条知识洞（同问无命中时才会拒答+落缺口）。

## 交付

| 件 | 交付 |
| --- | --- |
| 覆盖声明闸 | `_NO_COVERAGE_RE`（**保守**：只认「证据/资料/信息/数据 + 未覆盖/未涉及/未包含/不包含/中没有」与「无法回答/提供/确认/给出 + 问题/价格/信息/答案」两类说法）命中模型输出时：`answer` 换成 `refusal`（citations 清零、handoff=true）、`generated=None`（内容走既有拒答模板：固定文案 + 问句摘要 + 缺口号）——**一个知识洞只有一种形态** |
| 可观测 | `fallback_reason="no_coverage"` 随 complete 事件带出（与忠实度闸的 `"coverage"` 并列），日志/前端「模板回退」徽章仍按既有通道 |

## 验收（实测 + 钉子）

- **钉子（真引擎 + 替身 LLM）**：两条命中（忠实度闸不触发）+ 模型输出「当前已发布证据未覆盖刻字收费信息。」→ `answer.kind == "refusal"`、`citations == []`、`handoff is True`、`fallback_reason == "no_coverage"`、缺口照落（`db.add` 被调用）。
- **反向钉子**：正常作答（含「根据已发布证据」但不含未覆盖谓语）**不被误判**——`kind=answer`、`fallback_reason is None`。
- 门禁：集成 **943 → 945 passed / 0 failed / 0 skipped**；ruff 全过；前端未改（build/lint 7/0 回归确认）。

## 诚实披露

- **检测靠文案特征**（模型措辞不由我们控制）：只认两类保守说法；模型换个说法（如「暂未找到相关信息」）会漏检——**漏检的后果是退回本刀之前的行为**（记 answer + 引用），不是答错。
- **内容换成拒答模板**：模型那句「未覆盖…」不再出现在消息里，取而代之是既有的「抱歉，已发布资产里没有能回答这个问题的证据。问句摘要：…」。理由是一致性（同一种洞同一种文案），代价是丢了模型的具体措辞。
- **评测基线随演示库数据变化**：本次的 1.3pp 是治理动作的副作用，不是代码回归；golden 里引用已被取代的版本号（`13/v3`）属「期望过期」，以后发布改动应一并核对。
- 端到端证据是**本会话实测输出**（引擎替身用例 + 评测 stdout），未落成截图文件。
