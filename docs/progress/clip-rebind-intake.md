# 第 49 刀规格：源录像可改绑 + 上传回执指名来源（intake + 裁决）

日期：2026-09-11。分支 `feat/clip-rebind-49`（基于 main `266e96f`）。依据：`docs/progress/audit-9-closeout.md` 的 **P0-2** 与「下一刀建议 1」。**无新表无迁移**。

## 痛点（审计刀 9 实测）

1. **绑定不可改**：第 46 刀的绑定模型是「上传即绑 `recording_id IS NULL` 的 pending 候选，已绑的不改绑」。演示库 27 条 pending 全部绑在旧录像上之后，**再上传任何新录像都绑 0 条**——`routes/clips.py` 只有三个端点（列候选 / 上传 / 拣选），没有改绑或替换的入口。绑错一份录像 = 永久锁死，只能改库。
2. **演示自相矛盾**：README 的 0:45 演示稿要求「先上传源录像再拣选」，而现库状态下照做会得到「当前没有『尚无源录像』的待拣候选可绑定」，页头「当前源录像」还显示着旧录像——上传的与切的不是同一份。
3. **回执不指名来源**：拣选回执说「已从源录像切出真 mp4 片段」，但**不说切自哪一份**；上传回执的「绑定了几条」是前端拿上传前的候选数猜的，不是后端真值。

## 裁决（本刀**修订第 46 刀裁决 2**）

| # | 裁决 | 理由 |
| --- | --- | --- |
| 1 | **新增显式改绑端点** `POST /api/clips/recordings/{recording_id}/bind`：body `{candidate_ids: [int] \| null}`；`null`/缺省 = **全部待拣（pending）候选**；给了 id 就只改这些 | 绑定从「一次性的隐式副作用」升级为「可重复的显式动作」。**这就是对第 46 刀裁决 2（「已绑过的候选也不改绑」）的修订**——那条在单次演示里成立，但把「绑错」变成终态，是审计刀 9 的 P0 |
| 2 | 改绑**允许改已绑的 pending 候选**（覆盖旧绑定）；**已登记候选一律不许动**（回执锚已定，409） | 改绑的目的就是纠错；已登记候选的录像绑定是历史事实（拣选已经发生），改它不改变已切出的字节，只会让留痕失真 |
| 3 | 端点返回 `{recording_id, label, bound_count}`：**回执给后端真值**，不再让前端猜 | 回执必须说真话（审计刀 9 的观察） |
| 4 | 新增 `GET /api/clips/recordings`：按 `created_at` 降序，最多 20 条（`id/label/size_bytes/created_at`） | 没有列表就没法「改绑到哪一份」——只能改绑到刚上传的那份仍不解锁死 |
| 5 | 上传端点**仍做「上传即绑」**（无源录像的 pending），但响应**多一个 `bound_count`** | 保留第 46 刀的顺手动作为默认路径（演示仍然一步到位）；把真值换成后端给的 |
| 6 | 前端：页头「当前源录像」行加一个**录像下拉 + 「改绑」按钮**；勾了候选就只改勾选的，没勾就改全部待拣；改绑后回执「已把 N 条待拣候选改绑到《label》」 | 一键纠错要能在界面上发生；复用既有「已选 N」语义，不加第二个按钮 |
| 7 | 只校验候选**存在**（404）与**未登记**（409）；对「本来就绑着这份」的候选是幂等更新（`bound_count` 照计） | 与拣选的拒绝原子性同口径：校验先于任何写入 |
| 8 | 不做录像删除/替换字节/下载；不做「按候选分别绑不同录像」的多源模型（仍单源） | 删/换字节会留下悬空引用，属另一刀；多源留 Out（第 46 刀 Out 段已列） |

**回退点**：若 Owner 否决「改绑」这条契约修订，回退方式 = 删两个端点（bind/list）、上传响应去掉 `bound_count`、前端去掉下拉与按钮、README 演示前检查恢复成「复位 SQL」那段（本刀会把它删掉）。数据层零影响（无新列无新表）。

## 验收

1. **改绑全部**：演示库 pending 全绑在录像 A → 上传录像 B → `POST /recordings/B/bind {}` → `bound_count=27`、列表里 27 条 pending 的 `recording.recording_id` 全指向 B；已登记候选不变。
2. **改绑子集**：`{candidate_ids: [x, y]}` → 只动这两条；给已登记候选 → 409（且不写任何一行）。
3. **不存在**：unknown recording → 404；unknown candidate → 404。
4. **幂等**：对已绑在 B 的候选再 bind B → 仍是 200、`bound_count` 照计（不是错误）。
5. **列表**：`GET /recordings` 降序、≤20、字段齐；无 token 401。
6. **上传回执**：上传后 `bound_count` = 真实绑定条数（0 时也给 0，前端据此说「没有可绑定的」）。
7. **拣选回执指名来源**：前端回执里出现最近一次绑定/上传的录像 label（例：`已从《clip-b.mp4》切出 2 条真 mp4 片段`）。
8. **功能证据（真浏览器）**：上传一份**时长不同**的录像（如 10 分钟）→ 改绑全部 → 拣选一条时窗内的候选 → 资产字节 mp4 的 `ffprobe` 时长与该候选时窗一致，且**对象键与内容来自新录像**（用不同分辨率区分：新录像 320x240、旧录像 256x144，切出的片段分辨率随之改变）。
9. **门禁**：后端全量绿、ruff 净；前端 build 绿、lint 7/0。

## Out

- 录像删除/字节替换/下载、多源（按候选分别绑不同录像）、录像分页与搜索、改绑审计留痕（录像不是中台对象，第 46 刀裁决 1 同口径）、`PUT …/bytes` 那类「源录像替换后重切已登记候选」——已登记候选的字节不可追改（不可变回执锚）。
