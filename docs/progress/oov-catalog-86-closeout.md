# 第 86 刀 closeout：OOV 对照商品表（两类分说）

日期：2026-09-13。`feat/oov-catalog-86`。**无新表无迁移**。

## 背景（Owner 的两个判断）

1. 「顾客问到未上架商品是**必然**」——顾客不知道店里有什么，主动点名商品是最高价值的意图信号（真实客服里「你们有没有 X」是最常见问句之一）。问题不在能被问到，而在**回应方式**：此前用系统内部语言（「已发布资料里没有…」）打发，且**没查商品表**。
2. 「要建工单」——两种都建（需求信号/销售线索）。

## 交付

| 件 | 交付 |
| --- | --- |
| `oov_product_match` | 实体串 ↔ 商品名/类目名匹配，**两个方向语义不同**：实体 ⊂ 库内名（顾客用简称「保温杯」⊂「钛钢保温杯」，任意长度）；库内名 ⊂ 实体（要求库内名 ≥3 字——短泛词负例「星巴克杯子」曾被商品名片段「杯子」误命中）。补类目名与 `CATEGORY_ALIASES` 命中（「笔记本电脑」是类目、商品名是具体型号） |
| 两类文案 | 在库资料缺：「「X」的商品资料还在补充中，已记录并转人工处理。」；不在库：「本店暂时没有「X」这款商品，已记录并转人工处理。」（实体串仍过 `redact`） |
| 缺口语义收紧 | **不在库不落知识缺口**（补文档补不出来；缺口池语义=知识待补，不该被经营范围问题污染）；在库资料缺照落。**两种都建工单**（Owner 裁决） |
