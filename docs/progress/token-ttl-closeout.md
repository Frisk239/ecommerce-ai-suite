# 第 45a 刀 closeout：顾客令牌 TTL（`feat/token-ttl`）

日期：2026-09-10。规格 `docs/progress/token-ttl-intake.md`（Owner 六条裁决）；依据 `docs/roadmap-product-hardening.md` 第 45 刀的安全面那一半。**第 45 刀拆两刀走**：45a = 令牌 TTL（本刀）；**45b = 嵌入 widget**（loader + `/widget` + origin 白名单）待做。迁移 **0021**。

## 交付

| 层 | 交付 |
| --- | --- |
| 设置 | `customer_token_ttl_seconds`（默认 24h，与操作者 cookie 的 7 天**分开**，可 env 覆盖） |
| 数据 | `service_sessions.customer_token_expires_at`（迁移 0021）；**迁移内回填**存量「有令牌」会话为 `created_at + 24h`，操作者预览会话保持 NULL |
| 鉴权 | 新建 **`_authorize_customer_session`**（存在 + `compare_digest` 恒定时间比对 + **未过期**）——三处调用点（发问/反馈/联系方式）此前各抄一份同样的判断，现全部收敛；`expires_at` 为 NULL 视为**不可用**（严格，不给静默放行的口子） |
| 语义 | **过期与无效同 401、同文案、同响应头**（不向调用方区分「令牌曾有效」，也是既有口径的延续） |
| 签发 | 建会话即写 `now + ttl` |

## 验收（路线图要求「安全面变更必有越权/过期钉测」）

新文件 `test_customer_token_ttl.py` 七例，逐条对应 intake 的验收清单：

1. 签发即带过期时刻（`expires_at` 非空 + 落在 23–25h 量级窗内）。
2. 有效令牌照旧可用（控制组——TTL 不能把正常路径一起挡掉）。
3. **过期 → 401**；且逐字比对 detail，与「无效令牌」**完全相同**；`WWW-Authenticate: Bearer` 一致。
4. `expires_at` 挪到未来仍在期内 → 200（证明**不是「一律 401」蒙混**）。
5. NULL 过期时刻 → 401（严格口径）。
6. 三处端点（发问/反馈/联系方式）都 401，且**三处 detail 与响应头一致**（裁决 4 不能只在发问端点成立）。
7. 跨会话越权：A 的令牌打 B → 401（既有契约回归，TTL 改造不得放开这个口子）。

**迁移回填实测（演示库）**：升级后 `alembic=0021`，`customer_token IS NOT NULL` 的会话 38 条、**其中过期时刻为 NULL 的 0 条**（全部回填）、操作者预览会话被误回填的 0 条。CI 的新库无法复现这条路径（迁移在空库执行、UPDATE 命中 0 行）——本刀**如实记录**这一点，不假装 CI 覆盖了它。

浏览器：顾客主路径正常（新建会话 → 提问 → 有回答，无 401）；库内该会话 `expires_at > now()`。

门禁：集成 **788 → 795 passed / 0 failed / 0 skipped**；ruff 全过；本刀不动前端（`npm run build/lint` 未跑，无前端改动）。

## 评审处置

独立子代理评审：**可合并，无 P0/P1**（安全面核心契约——闸序前置、过期≡无效、NULL 严格、三处一致——实现与测试均到位；未越界做 widget）。已修 P2：

- 迁移回填口径注释：写死 24h **不随 env**（一次性历史修正，不是持续同步；将来调大 TTL 老行仍是 24h，属预期）。
- 反馈/联系方式两处补**同文案与同响应头**断言（原先只有发问端点钉了「同文案」）。

记债（P2，已记录未做）：①`customer_token_ttl_seconds` 被 env 覆盖时的签发行为无测试（settings 在 app 构建期定格，per-test 覆盖不便，留待后续）；②「过期令牌不消耗会话级配额」是静态判断（闸序：鉴权先于会话闸）但无直接测试；③迁移的 downgrade 未测（与既有各刀一致，迁移可逆性靠 alembic 机制）。

## 诚实披露

- **本刀不做刷新/续期/吊销**（路线图只要求 TTL）：令牌过期即需新建会话（顾客页每次进入本来就会新建）。
- **存量会话在演示库里已全部过期**（回填按 `created_at + 24h`，而演示库的会话都是 09-08/09-09 建的）——这不影响演示：顾客页每次「开始咨询」都签新令牌；操作者预览会话不受影响（无令牌、不走上闸）。
- 前端**没有**为「令牌过期」加专门 UI：过期走既有的统一错误呈现（与「会话不存在」同形），本刀不改前端——若要给顾客一句「会话已过期，请重新开始」，那是 45b 或后续的事。
