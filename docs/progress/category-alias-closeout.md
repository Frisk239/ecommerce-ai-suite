## 过程中的两次自抓（写下来防复发）

1. **真栈 500（KeyError('stock')）**：类目聚合结果没有单件 `stock` 字段，而 `render_stock_answer` 直接取它——**单元测试没测出来**（测试库没有「笔记本电脑」类目，走的是 else 分支），是端到端探针抓到的。修法：模板加类目分支 + 补两种形态的渲染钉子（有库存合计 / 未逐件设置）。
2. **正则复合词吃后缀**：「什么价格」被 `什么价` 匹配掉后剩「格」→ 评测集 `catalog-quote-new-product` 变红。修法：提纯词表只放原子词并保持长词在前；注释写明这条纪律。

## 诚实披露

- **别名表是保守的**：只覆盖 4 个类目（笔记本/手机/平板/电视），「图书/食品/器皿/家具/洗衣机」没有别名（「书」会撞「说明书」、「食物」歧义大）——**漏认照旧拒答留缺口**，宁可少认不误认。
- **类目聚合的库存是「计数 + 合计」**：不逐件展示（`stock` 是 mock 值，逐件铺没有决策价值）；「库存合计 1653 件」这种数字只在这类问句里出现，不是新口径。
- **词表放宽的代价靠回落兜**：`有…吗` 会把「有优惠吗」这类问句也送进库存路由器——查不到即回落（实测「有现货吗」照旧拒答），但多一次查库（一次 `select products`），无写入。
- 端到端证据是**本会话实测输出**（问句与答案原文），未落成截图文件。
