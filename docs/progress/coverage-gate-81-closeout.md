## 交付

| 件 | 交付 |
| --- | --- |
| 机理 | 症状=具名 OFF 问句「M&M white的条码是多少」6 次 3 拒（审计刀 16 C 轴）。**intake 的主假设（覆盖度被商品名稀释）经测量证伪**：coverage=0.429、hits=5——覆盖闸要求「覆盖度<0.4 **且** hits≤1」，两条都不成立，闸不触发。真因是 **prompt 证据行只给 `[来源：A-226·v1]`**：证据块「条码：000000000063」不含商品名，模型无法确认这条证据属于 M&M white，在忠实性约束下自述「证据未覆盖」→ 被 no_coverage 闸收成拒答（这条路径是随机的，因为取决于模型每次措辞）。降级模板（compose_answer）一直带标题，**只有 LLM 路径缺归属信息** |
| 修法 | `build_prompts` 加可选 `assets_meta`：证据行 -> `[来源：A-226「M&M white 规格（OFF）」·v1]`；标题过 `redact_contact`（对话资产标题=顾客首问，可能含联系方式）+ **结构净化**（折叠空白、剔「」[]——title 是顾客可影响面，换行会破「一行一证据」结构）；SYSTEM_PROMPT 加一句教模型用资料名核验实体归属；问句行同步升为 `redact_contact`（原 `redact` 对带分隔号码/短域邮箱覆盖不足，审计刀 8 判例） |
| 接线 | `chat_engine`：`assets_meta` 提为 meta 变量，compose_answer 与 build_prompts 共用一次查询（catalog 路径多一次只读查询，可忽略） |

## 偏离与诚实披露

- **golden_engine 未补 case 的理由**：本刀行为面（LLM 是否利用资料名核验实体）**原理上不进确定性层**（68 刀既定：LLM 依赖路径不进 CI；run_eval 直调 retrieve+compose 亦绕过引擎）。替代钉子：prompt 契约单测 ×4（资料名进 prompt/结构净化/问句行掩码/无 meta 退化）+ vendor 引擎级 wiring 断言（全链证明 meta 真的传到 build_prompts 并进 user prompt）；结果面证据=live 5/5（两轴独立）+ 压力场景。
- **记债**：①中间地带——问句「头名词匹配、修饰语不可证伪」（「Erdbeeren 巧克力」vs 库里 Erdbeeren 规格）会给该资产的真值，不判为错答但不够保守；②「钛钢保温壶」一次 kind=answer 内容是「未提供具体数值」而证据实含 500ml（保守方向误述，跨会话不稳定）。
- 评审探针在演示库新建会话（301-303 等）；本刀验收会话一并留存（均为真实问答，演示无害）。
