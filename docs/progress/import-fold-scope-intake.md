# 第 64 刀 intake：导入货折叠语义对齐（只折「导入且未发布」）

上一刀：第 63 刀 `fallback_reason` 进指标（PR #93）。本刀取审计刀 12 **记债 C-P2**
「折叠组在所有 tab 生效」：`已发布` tab 也会把 20 条 OpenFoodFacts 规格折叠
（published 56 → 可见 36 + 折叠头），与「导入货」的语义（**待人洗待办**）不齐。

## 判据（不是观感裁决，是语义对齐）

- 折叠的**动机**（第 59 刀）：待人洗队列里导入货占绝大多数（180/194），首屏被
  待办噪声铺满——折的是**待办**，不是「导入」这个来源本身。
- 已发布的导入行是**线上证据**：客服引用它（citations）、连接层读它——把它折进
  表尾，「已发布」tab 凭空少 20 条，用户找一个刚被引用的 OFF 规格文档要在折叠头
  里翻。
- 所以单一规则：**折叠 = 导入 且 未发布**（实现名 `isFoldedImport = isImportedSource && !isPublished`——评审订正：本 intake 初稿写的 `isFoldedSource` 与实现不一致，以实现为准）。
  已接入/待人洗的导入行照旧折（那正是待办）；已发布的导入行进主行。

## 本刀范围（前端小刀）

1. `workQueue.isFoldedImport`（谓词单一来源，复用既有 `isImportedSource`/`isPublished`）。
2. `AssetsListPage` 折叠组改用该谓词；折叠头文案改「数据集导入待办 N 条」并注明
   已发布导入行在主行。
3. 自动展开逻辑不动（`primaryRows.length === 0 && importedRows.length > 0`——
   搜索只命中未发布导入货时仍自动展开；命中已发布导入货时它们本来就在主行）。

## 明确不做

- 不改默认视角/总数/次序（第 59 刀口径）。
- 不动来源筛选 chips（按当前 tab 实际行统计，与本刀无涉）。
- 不做前端单测框架（本仓前端验收 = build/lint + 浏览器点穿，与历刀同口径）。
