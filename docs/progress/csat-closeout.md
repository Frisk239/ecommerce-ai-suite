## 评审处置（两轴独立只读子代理：规格符合性 / 工程健壮性）

评审报 **P0×2**（都是前端状态机真 bug）+ **P1×2** + P2 若干；全部实修并复核。

- **P0-1 换会话不重置评分态**：`rated`/`ratingComment` 是页面级 state，`startSession` 只重置了 messages/feedback/工单标记——**同一 Tab 给会话 A 打完分 → 点「新会话」→ 新会话页脚直接显示「谢谢反馈：你给这次服务打了 N 星」，评分条永不出现（CSAT 静默丢样本），文案还把 A 的分安到 B 头上**。修法：`startSession` 成功分支补 `setRated(null)` / `setRatingComment('')` / `setRatingSending(false)`。**复核**：浏览器里真打分 5 星 → 点「新会话」→ 再问一句 → 页脚重新出现「这次服务怎么样？」（修前是旧致谢文案）。
- **P0-2 打回理由跨任务残留**：`TaskDetailDrawer` 始终挂载（`task=null` 时内部 return null，组件实例不卸载），`rejectReason`/`rejecting` 跨任务存活——**打开任务 A 填「画面糊」→ 关闭 → 打开任务 B → 点确认打回 → B 的 `last_error` 里写着 A 的理由**（错误理由落库给生成方看）。修法：挂载点加 `key={detailTask?.id ?? 'none'}`（按任务重挂载）。**复核**：A 填理由 → 关闭 → 重开 → 理由框收起且为空。
- **P1-1 掩码顺序的钉子原来是伪钉**：`test_build_csat_masks_before_truncating` 把手机号放在 60 字截断线**之内**——「先掩后截」与「先截后掩」输出逐字相同（评审实测 `same: True`），那条被文档反复强调的 PII 保证实际没被钉住。修法：号码挪到跨界处（`"前"*55 + "13800138000"`），此时先截会留下 `13800` 残片而先掩不会——断言 `"138" not in text` 且 `"*" in text`；另拆一条常规路径用例保留整段掩码断言。
- **P1-2 端到端证据**：评审在 closeout 落盘前跑的，没看到浏览器走查记录——验收 1–6 条就是该次走查的实录（打分/掩码/徽章/打回 UI 均为界面回显），本 closeout 已补「诚实披露」里的库内改动说明。

P2 顺手修六条：**越界分口径统一**（原来 `ratings_last_7d`/均值含越界分而分布丢弃，会出现「条数 ≠ 分布之和、均值被拉偏」——现在三处统一当它不存在，用例改名 `..._is_ignored_everywhere`）；**均分改四舍五入**（`round(4.25)=4.2` 是银行家舍入，展示口径应为 4.3，补 `test_build_csat_average_rounds_half_up`）；`IntegrityError` 只翻译「会话唯一约束」冲突（FK 违约等照旧上抛，别把「会话刚被删」误报成「已评过分」）；`test_return_flow_integration` 模块 docstring 的旧口径（helpful=true 422）订正；低分用例补「**不建工单**」断言（裁决 9 三条齐了）；前端 `s.rating != null`（后端形状缺失时不会渲染「★ undefined」）。另补 6 例边界钉子（空白留言 → None、留言恰 500 收、空会话可评（后端契约如实钉住）、多会话批量星级不串、打回理由纯空白/恰 200 字）。

**记债**（评审提出未修）：评分**不做改评**（v1 唯一约束，顾客点错只能重开会话）；留言全量查看属 Out（仪表只给最近 3 条）；`_build_csat` 对 `redact_contact` 的返回值无静态类型兜底（仓内无 mypy，运行期有 `if comment` 前置保护）。

## 诚实披露

- **验收动过演示库**：顾客会话 #83/#84（浏览器验收建的）、会话 #84 的评分与 thumbs-up 两条真实记录。这是验收的产物，不是代码路径。
- **「一次性提示」的实现口径与 roadmap 字面不同**：roadmap 写「会话结束（操作者回流时或顾客关闭）触发」——本仓顾客通道**没有**「顾客关闭会话」这个事件（`closed_at` 只在操作者回流登记时落），所以本刀做成「页脚常驻、评过即收」。**回退点**：若将来加顾客侧结束动作，把评分条改为结束态触发即可（端点与表不变）。
- **低分不联动任何治理动作**：≤2 分不撤销验证、不建缺口、不建工单（intake 裁决 9）——CSAT 可能因为物流慢，把它当「证据有问题」是误伤；要复审走 thumbs-down（那才是证据语义）。
- **留言最长 500 字、仪表只展示最近 3 条 × 60 字**：留言不是评论区，全量查看属 Out（没有留言列表页）。
- **评分不可改、不可删**：v1 唯一约束；「改评」是 Out（顾客点错只能重开会话——顾客通道本来也不做会话续接）。
- **前端无单测**（本仓一贯）：评分条/徽章/面板的验证靠 build+lint+真浏览器点穿。
- 端到端证据是**本会话实测输出**（上列文案与库内行均为命令/界面回显），未落成截图文件。
