## 实修

### P0

1. **会话详情恒回 `host_origin: null`**（A-P0-1 = B-P1-3 = C-P0-2，三轴同时命中）：`SessionDetail` 继承了 `host_origin` 字段却**没在构造时传**——列表给 `http://localhost:5173`、详情给 `None`，而第 54 刀 closeout 明写「列表与详情同源」。修法：`get_session` 补 `host_origin=session.host_origin`（+ 前端 `ServiceSessionDetail` 类型补字段 + 详情断言钉子）。
2. **治理台「待补缺口」里躺着客服当下已能答的问题**（C-P0-1）：「你们卖什么？」「笔记本电脑多少钱？」两条 open 缺口，而顾客同问句实测分别答出目录列举与类目价——同一句话，治理台说「去补文档」、客服说「有」。修法两层：①**产品面**：`run_ask` 的目录回落分支里，同问（`normalized_question` 相同）的 open 缺口**一并收掉**（缺口是「知识待补」；目录能答说明不需要补文档；`resolved_by_asset_id` 如实留 NULL——不是靠文档补上的），补钉子用例；②**存量**：演示库两条陈旧缺口（`id=9/12`，创建于目录回落之前）手工关闭（下表披露）。

### P1

3. **类目问价被「商品名含类目名」劫持**（B-P1-1）：`_quote_answer` 先走单品路径，商品「WANDS 家具（演示）」含完整类目名「家具」→ 「家具多少钱？」被答成**这一个商品**的价（89.9 元），类目聚合（件数/区间/未定价计数）被静默吞掉；再加一件不同价的家具就答错。修法：**先类目、后单品**（类目路径自带纯度闸——问句扣掉类目名后还有实质内容如具体型号，就不会命中，此时才走单品）。钉子：「家具含两件不同价 → 答类目区间且 `tool.arg` 是类目」+「具体型号仍走单品」。
4. **导入脚本不写资产来源**（B-P1-2，与审计刀 10 同类问题的残留面）：OFF/评论资产经登记通道建，`source_kind` 是服务端定值 `upload`；迁移回填只在存量上跑——按 README 顺序（先迁移再灌数据）**重置库后 220 条资产的来源词消失**。修法：两个脚本在导入后按与迁移同源的形态补写（`review_import` / `openfoodfacts`）。
5. **迁移用例第三次踩「升到 head」**（B-P1-4）：0028 用例自称按第 51 刀教训整改，自己却仍 `upgrade(cfg, "head")`——0029 一动 `source_kind` 就会把断言打红。修法：钉到 `0028` 为止；并**加一条「拆细后无 `open_dataset` 残留」的断言**（此前静默漏行无发现机制）。
6. **商品页首屏 115 张卡（折叠判据失效）**（C-P1-2，第 50 刀回填价的副作用）：原来「已定价=展示、未定价=收起」，全店有价后 `featured=115 / rest=0`，UX-A1 的可扫读口径被打破。修法：**按数量收口**（`FEATURED_LIMIT=24`，已定价优先排序不变，其余进折叠区，文案改「其余 N 件（已定价优先排在前面）」）。
7. **两处披露订正**（A-P1-1 / A-P2-1）：第 52 刀 closeout 写「演示数据暂时看不到区间」**不成立**（器皿类目有两价，实测 `器皿多少钱？`→「价格 99元–129元」）；第 55 刀商品分布漏了 1 条运营手建（NULL，共 115 件）。

P2 顺手：`host_origin` 入库前截断到列长 255（白名单被写成超长不该 500）；类目聚合**混币种直接拒答**（跨币种比大小无意义，不给「3元–5美元」的假区间）；类目轨迹的价格段复用 `format_price`（不再手搓 `//100 元`）；来源词旧的 `open_dataset` 注释四处订正（models/products/types/README 标题）；`CONTEXT` 来源词条补到 11 值。

## 记债（未修，逐条给理由）

- **顾客口语覆盖不足**（C-P1-3）：`笔记本多少钱？`（类目别名）、`笔记本电脑怎么卖？`（报价词缺「怎么卖」）、`你们有笔记本吗？`（库存词表只认全名）三条全拒答——演示观众用口语即穿帮。这是**能力扩展**（类目别名表 + 报价意图词 + 有X吗路由），列下一刀首选（审计三路里两路都指向它）。
- **「证据未覆盖」却挂引用**（C-P1-1）：有弱命中时走 RAG，模型答「证据未覆盖…」但消息仍带 citations、也不落缺口——同一种知识缺失因检索有无边际命中产生两种系统状态。属检索质量面，需在「弱命中是否降级为拒答」上做判断（动忠实度闸口径），不在本刀。
- 工作队列默认视角（首屏 194 行 / 180 导入，Owner 观感裁决）；评分可改（语义决定）；分币种报价（v1 单币种约定）；`.slice-test.mp4`（5s）可被绑但时间码全超（拣选 422 有放回兜底）；0028 的 down 按值回收（升级后新导的行也会被翻回 `open_dataset`）；前端来源词合法性判据用展示词表反推（权威在后端 `SOURCE_KINDS`，将来漏改会「URL 写着筛选、实际全量」而不报错）。
