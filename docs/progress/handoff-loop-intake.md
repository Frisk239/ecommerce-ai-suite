# 第 42 刀规格：转人工真闭环（intake + Owner 裁决）

日期：2026-09-10。分支 `feat/handoff-loop`（基于 main `6d592ee`）。依据：`docs/roadmap-product-hardening.md` 第 42 刀；领域边界见 `CONTEXT.md` 词条「转人工」「知识缺口」。

## 痛点（路线图最痛#2）

- 显式要求转人工被当知识题：`catalog_tools._HUMAN_RE` 只是「不抢」，显式「转人工」继续走检索 → 多数落拒答 + 落知识缺口（实测）。
- **前端「已转人工」徽章是空头支票**：`handoff=True` 会渲染徽章，但后面没有任何东西接住它（无工单、无联系人、无预期）。
- 「投诉/举报」全仓无任何识别，归宿是缺口。

## Owner 裁决（实现按此，不再回头问）

| # | 裁决 | 理由 |
| --- | --- | --- |
| 1 | **一个会话一张工单**（`session_id` 唯一），由该会话**第一次** handoff 事件创建：显式请求或拒答都算；后续复用 | 既不漏「已转人工」的承诺，又不会让一次会话的多次拒答刷出多张工单（工单是「这段对话要人接」，不是每条消息一张） |
| 2 | **显式请求**的回复带工单号回执：「已记录工单 H-0001，工作时间 4 小时内回复。」+ 一句「可在下面留下联系方式，方便我们联系你。」；**拒答消息文本不动**（避免动 `REFUSAL_CONTENT` 与既有全等断言） | 顾客明确要人时才需要号码；拒答已用徽章表达转人工 |
| 3 | 工单号 **`H-{id:04d}` 由 PK 派生**（不落独立列、不建序列表） | 与 `G-xxxx` 同款；Postgres serial 天然唯一，无 max+1 竞态 |
| 4 | 词表快路径 = `转人工|找人工|要人工|人工客服|真人|投诉|举报`——**不含裸「人工」**（会误伤「人工智能」），且插在 `run_ask` 分派**最前置**（订单/库存快路径之前） | 显式要人优先于一切工具 |
| 5 | 模型提议路径：`propose_prompt` 加第三选项，输出 `TOOL: handoff {}`；解析时**先识别 sentinel、不进 registry**（`test_registry_contains_exactly_three_readonly_tools` 是精确集合断言，注册进去必破） | 保持注册表「三个只读工具」的既有契约 |
| 6 | 联系方式表单：**姓名 + 留言必填；邮箱/电话可选；整表可跳过**（不填也能拿到工单） | 强制留联系方式伤转化；工单本身已存在，联系方式只是让它可回访 |
| 7 | PII：**落库存原文**（0038「字节不动」），**操作者面出口必掩** 电话/邮箱（走 `machine_wash.redact`）；姓名不掩（操作者要称呼对方，且现有掩码粒度只管电话/邮箱）。顾客自己回显不掩 | 沿用 0038 出口掩纪律，不新造粒度 |
| 8 | `complete` 载荷追加**运行时可选键** `ticket_id` / `ticket_no`（顾客可见）——**不走 `expose_gap_id` 白名单**（缺口号是内部 ID，工单号是给顾客的回执） | H 号是顾客的，不是内部的 |
| 9 | 操作者面：会话列表加 `pending_ticket_count`（照现有批量 group-by 并第二个统计）+ `seg` 筛选「全部 / 待处理工单」（先例：资产页缺口分段）+ 置顶 + `POST /api/service/handoff-tickets/{id}/resolve`（照 `confirm_return`/`register` 的状态机 + 409 先例） | 路线图只要求过滤/置顶/计数/解决，不另开列表端点 |
| 10 | **开 ADR 0046**（新表 + 新意图路径 + 工单/缺口边界）；迁移用 **0020**（0018/0019 已占） | 「动数据契约必 ADR」排期原则 |

## 领域边界（写进 ADR 与词条，防漂移）

- **工单 ≠ 缺口**：缺口是「知识待补」（发布文档即关闭，机制在治理台）；工单是「顾客要人」（人回复后置 resolved）。同一会话可能两者都有——那正是两件事都成立。
- **仍然没有坐席队列**：工单是「有回执的待办」，没有分派、没有坐席、没有 SLA 计时器。词条 v2 要把「v1 只是消息种类」改成「v2 有工单+回执+联系方式，仍无坐席队列」。
- 「客服工单产品」仍在 `_Avoid_`。

## 会破的既有断言（预期，需一并改）

- `apps/api/tests/test_product_operable.py:398-410` 的 `"卖什么？转人工"`：现在期望 `kind=="refusal"` + `gap is not None`，本刀后应为 `kind=="handoff"`、无缺口（正是本刀要改的行为）。
- 词表快路径让「投诉/举报」不再产生知识缺口——语义变化，closeout 如实写 + 补钉测。

## Out

- 坐席队列/分派/SLA/工单优先级/附件；工单的顾客端查询页；短信/邮件真实外发（回执只是话术，不外发——若仍为话术，closeout 必须如实标注）；D 类之外的 UI 重排。
