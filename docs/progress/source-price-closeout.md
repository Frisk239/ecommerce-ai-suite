## 验收（实测）

1. **资产来源**：`select source_kind, count(*) from assets group by 1` → **review_import 200 / open_dataset 20 / upload 12**（原 232）/ mcp_registered 16 / session_backflow 9 / clip_pick 8 / material_generated 2——其余一条没动。
2. **商品来源**：open_dataset 112（= Wikidata 91 + OFF 20 + WANDS 承载 1，形状 SQL 逐项对上、unexplained=0）/ seed 2 / NULL 1（手建行，来源与价都未被覆盖）。
3. **演示价**：`count(*) / count(price_cents) FROM products` = **115 / 115**（原 3）；两条种子价未被改动（300 / 12900）。
4. **问价可答**（本刀补的关键一步）：「钛钢保温杯多少钱？」→ **catalog 工具式**回答「钛钢保温杯（器皿）售价 129元。」（citations 恒空、kind=answer、fallback=false）；「你们卖什么？」→ 「本店在售商品共 115 件，**均已定价**」+ 已定价前 8 件（不再有「其余未定价」）。**界面**：商品卡显示单价 + 来源 chip（种子 / 开放数据集），资产列表显示「评论导入」。
5. **不抢**（评审 P1 修复后实测）：「保温杯刻字怎么收费？」→ **不走**报价模板（交回 RAG，答「证据未覆盖收费信息」）；「退货运费多少钱？」照旧走 RAG 答政策。
6. **迁移可逆**：临时库 `upgrade head → downgrade 0025 → upgrade head` 往返通过；降级后 `review_import`/`open_dataset` 归零、**两条种子价仍在**（评审 P0 的钉子）。
7. **门禁**：集成 **909 → 917 passed / 0 failed / 0 skipped**；ruff 全过；前端 build 绿、lint 7/0；大集评测 **65.0/75.0 零漂移**（结构性：大集直调 retrieve+compose、不过引擎回落分支），已补进 `docs/research/rag-eval-report.md`。
8. **端到端（真浏览器）**：商品页看到「单价 2999 元 · 开放数据集」等卡片与只读来源行；资产列表来源列出现「评论导入」。

## 评审处置（两轴独立只读子代理）

**P0×1 + P1×2** 全部实修；P2 顺手 3 条。

- **P0-1 迁移降级会清掉迁移前就存在的价**：down 的价格清理按「类目 + 值正好等于基准」匹配，**无法区分「0026 写的」与「本来就是这个值」**——评审实测：降级把两条种子价（300 / 12900）一起清掉，`priced` 从 115 掉到 1（只剩一行手改价）。修法：清理条件加 `source_kind IS DISTINCT FROM 'seed'`，并在迁移注释里如实记下残余风险（非种子、迁移前就手改成基准价的行仍会被清——单向回填的固有代价）。**钉测**：迁移用例里插一行「种子形态价」并断言降级后仍在。
- **P1-1 报价模板抢答「商品名 + 服务费」问句**：`PRICE_RE` 含「收费」，`match_product` 的 LCS≥2 又能靠商品名命中，于是「保温杯刻字怎么收费」「钛钢保温杯怎么保养，收费吗」被答成「售价 129元」——而这类问句该走文档（演示库里恰好有「定制刻字服务怎么收费」的资产）。修法：加**纯度闸** `price_residual`——扣掉商品名、价格词与问价虚词后必须为空（问句主体就是「商品名+问价」）才回落。**钉测**：3 例服务/规格问负例 + 纯函数用例。
- **P1-2 本刀核心改动缺真钉子**：原端到端用例的夹具里 `retrieve` 为空，走的是**老的空命中回落**——删掉引擎里新加的两行它照样绿；评测报告里「catalog-quote 那例同时覆盖有命中路径」的说法也不成立（该 example 同样空命中）。修法：用例先**发布一份含商品名的资产并断言 `retrieve` 非空**，再断言回答仍是行价；评测报告那句改写为事实（并注明新路径由该用例钉）。
- **P2 顺手**：ADR/intake 里「已发布资产 250+」订正为实测 56 条（471 块）；前端来源判空改 `!= null`（旧响应缺字段时不渲染空行）；`_PRICE_RE` 用原始串避免无效转义告警。

## 诚实披露

- **演示价是 mock**：`CATEGORY_DEMO_PRICES` 九个数与第 41 刀两个种子价同口径（出处=seed 的 DEMO 基准），**非真实售价**；README、常量注释、迁移注释三处都写明了。真实数据集自带的价（若有）没有被使用。
- **来源是「回填的既成事实」，不是导入时记下的**：四条灌入脚本（`scripts/realdata/*`）都不写来源——本刀按脚本写死的命名形态在**存量库**上回填。**重新跑脚本导入的新行仍会是 `upload`/NULL**（刷新数据要不要带来源，intake 列为 Out，需另开一刀）。
- **按类目问价仍答不出**：「笔记本电脑多少钱？」匹配不到商品名（`match_product` 匹配**商品名**），走 RAG → 拒答 + 落缺口。本刀只修了「按名问价」，按类目问价留作后续（它其实是「类目→商品」的映射问题，不是价格问题）。
- **迁移判据是形态而非身份**：`spec_schema='{}'` + 六类目、标题含「评论 ·」/「规格（OFF）」——若将来有人手建同形态的行，会被打上同样来源（当前 API 强制类目模板，运营造不出 `{}`，实际不可达）。
- **验收动过演示库**：0026 回填了 200 条资产来源、112 件商品来源与 112 行演示价；新增一份「钛钢保温杯调价通知」资产（端到端钉子用，已发布）。
- 端到端证据是**本会话实测输出**（SQL 计数、SSE 文本、界面文本均为回显），未落成截图文件。
