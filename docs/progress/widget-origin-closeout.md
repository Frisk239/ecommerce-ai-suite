# 第 54 刀 closeout：嵌入宿主的来源站点落库（`feat/widget-origin-54`）

日期：2026-09-11。依据：审计刀 8 起记债、审计刀 9/10 两次复核仍成立的**最后一条产品面缺口**——「widget 只落 visitor_id、不落宿主 origin」。迁移 **0027**。

## 交付

| 件 | 交付 |
| --- | --- |
| 数据面 | `service_sessions.host_origin`（迁移 0027，String(255) nullable）：过闸的 `X-Widget-Origin` 的**归一值**（小写、去尾斜杠，与 `_widget_gate` 的比对口径同源）在建会话时落库；**独立访问为 NULL**（没有宿主）；**不做回填**（存量会话没有这个事实，不编造） |
| 操作者面 | `SessionOut/SessionSummary` 带 `host_origin`（列表与详情同源，无新查询）；客服页会话行在「访客 xxxxxx」旁显示**「站点 shop.example.com」**（协议前缀在展示层剥掉，title 给完整 origin） |
| 边界 | 与 visitor_id 同一道闸：只有**过闸的嵌入请求**才落（独立访问自带该头会被闸 403 or 不落——见验收 3） |

## 验收（实测）

1. **嵌入路径（真浏览器 + 演示宿主页）**：打开 `apps/web/public/embed-demo.html` → 点启动钮 → iframe 指向 `/widget?visitor=bc1988d4-…` → 面板内「开始咨询」→ 库里会话 **102**：`visitor_id=bc1988d4-…`、**`host_origin=http://localhost:5173`**。
2. **操作者可见**：客服页会话行 `#102 → 顾客 · **站点 localhost:5173** · 访客 bc1988d4`（第 45b 刀的访客徽章旁边多了站点徽章）。
3. **独立访问**：`/customer` 直开建的会话（#101）两个字段都是 NULL；独立访问带 `X-Widget-Origin: http://evil.example` → **403**（闸先行），不会落库。
4. **归一**：大小写/尾斜杠按闸的归一值落库（`HTTP://LOCALHOST:5173/` → `http://localhost:5173`）。
5. **门禁**：集成 **927 → 930 passed / 0 failed / 0 skipped**（新增 3 例：落库 + 操作者可见 / 归一 / 独立访问为 NULL）；ruff 全过；前端 build 绿、lint 7/0；迁移 0027 在临时库 `upgrade head → downgrade 0026 → upgrade head` 往返通过。

## 诚实披露

- **来源是「前端自报 + 服务端白名单」**，不是强身份：该头由我们的 widget 前端从 `document.referrer` 读出后带上，宿主若自己伪造请求仍可能过（第 45b 刀起就在 README 局限段写着；要彻底堵死需在边缘/反代拦文档请求——本仓是 dev 栈，没有这层）。本刀只是把**已经用于闸判定的那个值**落库，没有提高它的可信度。
- **存量会话不回填**：`host_origin` 为空表示「没有这个事实」（独立访问/操作者预览/本刀之前的会话），不区分「历史嵌入会话」与「独立访问」——历史嵌入会话的宿主来源当时没有记录，无法事后知道。
- **不做的事**：按站点统计/筛选（`stats` 与资产列表都没有站点维度）、多站点白名单的分组管理、站点级限流。要按站点看数据得另开一刀。
- 端到端证据是**本会话实测输出**（库内行 + 界面文本回显），未落成截图文件。
