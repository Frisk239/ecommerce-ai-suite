# 第 62 刀 intake：类目别名扩表到 9/9 类目 + 类目问句纯度闸补到库存路径

上一刀：第 61 刀演示库探针清理（PR #91，`docs/progress/demo-reset-closeout.md`）。
本刀取自**审计刀 12 的两条遗留建议之首**：「类目别名扩表（4/9 类目）+ 歧义评估」。

## 一手证据（本刀开刀前实测，非推断）

演示库 9 个类目（`products.group by category`）：笔记本电脑 34 / 食品 21 / 图书 19 /
电视机 16 / 智能手机 10 / 平板电脑 8 / 洗衣机 4 / 器皿 2 / 家具 1。

**报价路径**（`try_price_answer` 直调演示库）：

| 问句 | 开刀前 | 说明 |
| --- | --- | --- |
| 笔记本/手机/平板/电视 多少钱 | 答类目价 | 第 56 刀的 4 个别名 |
| 食品/图书/洗衣机/器皿/家具 多少钱 | 答类目价 | **类目名本身**命中（字面） |
| 电脑/彩电/零食/吃的/食物/书/书籍/杯子 多少钱 | **拒答 + 落缺口** | 别名未覆盖（审计刀 12 C-P2） |
| 说明书/书桌/电脑包/手机壳 多少钱 | 拒答 | 别名未覆盖时自然拒答 |

**库存路径**（`query_stock` 直调演示库）——**这才是本刀的重头**：

| 问句 | 开刀前 | 应然 |
| --- | --- | --- |
| 你们有笔记本吗 / 笔记本有货吗 | 类目聚合 | 类目聚合 ✓ |
| **手机壳有货吗** | **「智能手机共 10 件」** | 回落检索（问的是配件） |
| **电视柜有货吗** | **「电视机共 16 件」** | 回落检索（问的是家具） |
| **平板支撑有货吗** | **「平板电脑共 8 件」** | 回落检索（问的是运动） |
| **笔记本电脑包有货吗** | **「笔记本电脑共 34 件」** | 回落检索（问的是箱包） |
| 保温杯有货吗 | 单品 钛钢保温杯 | 单品 ✓（不能被类目吃掉） |

根因：第 56 刀把 `CATEGORY_ALIASES` **接**进了库存路径，却只在报价那条装了纯度闸
（`price_residual`）；`_category_stock` 判的是裸 `token in question`。**这就是本项目
第三次踩同一个坑：同一道闸只装在两条入口路径中的一条上。**

## 本刀范围（裁决）

1. **别名扩到 9/9**：每类目至少一个顾客常用短称；歧义面交给纯度闸，不靠字面保守。
2. **库存侧补纯度闸**（`stock_residual`），与报价侧同精神但**各自一张虚词表**
   （问价词 vs 问货词，合并会互相放水）。
3. **候选表单一真源**（`category_targets`）：别名在前、库内类目名在后（长名优先），
   两条路径共用表、各装各的闸。
4. **单字别名缺陷**：`书多少钱` 走 `price_residual` 时 `lcs_fragment` 长 1 < 最小长度 2，
   永远剔不掉 → 类目 token 改**字面剔除**（`category_question_residual`）。
5. **类目先于单品**（库存侧，对齐报价侧审计刀 11 P1）：商品名含完整类目名时，
   先走单品会把「你们有家具吗」答成**这一个商品**。

## 明确不做

- **不收会把单品问价降级的别名**（「保温杯」→器皿：会吞掉「保温杯多少钱」的单品行价）。
- 不动检索/生成路径（故评测报告只需复核零漂移，不需 before/after 对照）。
- 不改 `CATEGORY_ALIASES` 之外的类目判定（不引入分词库/模糊匹配）。
- 不加金标集条目：评测 runner 直调 `retrieve+compose`，**不经目录回落**，
  类目问价不在其覆盖面上（这是评测尺的已知边界，不是本刀新增）。
