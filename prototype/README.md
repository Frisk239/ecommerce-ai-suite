# 电商 AI 套件 · 操作台原型（prototype/）

纯前端可点击原型：八块能力都有入口，共用**一份内存 mock store**（`localStorage` 持久化），数据全部 mock，不调任何模型与后端。领域词汇与规则跟 `CONTEXT.md` 与 `docs/adr/` 一致。

## 运行

```bash
cd prototype
npm install
npm run dev     # 打开终端里给出的地址（默认 http://localhost:5173）
```

顶栏「重置演示」可随时把数据恢复成初始种子（清 localStorage 也可以）。

## 三条闭环怎么点

### 1. 接待闭环（总览 → 客服）

1. `中台 · 资产` 打开 `A-0002 钛钢保温杯 · 规格文档`（待人洗）：**材质**是弃权（原文未找到），净含量是机洗抽取值（待确认），发布按钮禁用并写明缺项。
2. 净含量旁点「确认」（一键确认机洗值），「补填」材质（如 `钛钢`）→ 发布按钮解禁 → 发布 → 确认（确认框写的是「净含量、材质」——字段跟商品类目走）。
3. `中台 · 商品`：保温杯显示 净含量 500ml / 材质 钛钢（器皿类目没有保质期字段），来源芯片 `A-0002 · v1`。
4. `AI 客服` → 新会话 → 问「保温杯的净含量多少？」：回答带引用芯片 `A-0002 · v1`，点芯片直达只读证据视图。
5. 问「这个水喝起来有点发甜」：**拒答 + 转人工**（该口径只在待人洗对话 A-0006 里，未发布不可引用）。
6. **发布 A-0006 后再问同一问题**：回答「根据已发布的客服对话记录：…」并引用 `A-0006 · v1`——客服走的是真检索（`retrievePublished`），新发布立即可用。
7. 「结束并回流登记」：中台出现新对话资产（已接入），客服再问相关内容仍检索不到；治理发布后同样可被引用（回到第 6 步的模式）。
8. 回到资产详情对已发布资产「开修订」：修订期间客服仍引用旧版本号，修订发布后指针前移。
9. `销售考核`：题库来自**全部已发布对话资产**（含你刚发布的那条），新回流发布的对话当天就能成为考题。

### 2. 内容闭环（素材/切片 → 运营）

1. `素材中心`：任务 T-0001「登记到中台」→ 新素材资产（已接入），页面明示「未发布，客服还不能用」。
2. `直播切片`：勾选候选 → 「拣选登记」→ 每条成为已接入视频资产。
3. `运营 Agent`：连点「执行下一步」走完 读商品卖点 → 调素材（第一次会 429 失败，点「重试失败步骤」）→ 组装文案；刷新页面轨迹不丢。
4. 「投放发布」二次确认；取消则不出现已投放。注意这是渠道动作，不是治理台的「发布资产」。

### 3. 能力闭环（微调 → 客服切底座）

1. `模型微调`：导出列表**只有已发布**（待人洗/已接入不出现）；勾选 → 导出 → 记录里保留资产 ID 列表。
2. `AI 客服` 切「微调」：回复口吻变化，消息带「微调底座」徽章。
3. `销售考核`：场景来源只能是已发布对话资产（`A-0005 · v1` 芯片可回溯）。

### 连接层（MCP）

`连接层` 页：四个工具（检索已发布 / 取资产 / 登记 / 导出），**没有发布**；「外部 Agent 检索」演示只返回已发布（试搜「续命杯」= 0 条），「登记」演示产生已接入资产。

## 第二轮：视觉重做 + 交互复审（2026-09-05）

第一轮后用户反馈视觉太丑、并要求审查交互闭环。第二轮做了两件事：

**视觉重做（v2）**。先用截图做挑剔诊断（品牌色过胆怯、卡片无海拔、徽章廉价、排版无重量对比、间距无节奏），再调研 Linear 设计语言与优质 shadcn 仪表盘做法，落地为：哑光画布 + 白面板分层微阴影、统计卡（小标签+大数字+语义图标块）、闭环卡步骤流、圆点语义徽章、分段筛选控件、侧栏选中指示条 + 底部店铺卡、主按钮内高光 + active 缩放 0.97、对话区头像与时间戳。VLM 视觉评审从「廉价脚手架感」提升至 8–8.5/10（详见 UX-NOTES）。

**交互复审修复的三个真实问题**（全部浏览器复测通过）：

1. **客服库存问题会「猜」商品**：未识别到商品词时兜底回答第一个商品的库存，属幻觉风险 → 改为反问澄清（「请问您想查询哪款商品的库存…」）。
2. **登记资产丢失原始内容**：`registerAsset` 未保存内容、机洗用通用占位文本顶替，导致回流对话发布后检索不到真实转写（闭环断裂）→ 资产保存 `sourceContent`，机洗从原始内容生成工作版本并附机洗说明。端到端复测：会话回流 → 机洗 → 发布 → 连接层检索命中 `A-0007 · v1`。
3. **修订发布后客服口径不跟随**：售后回答是硬编码文案，指针前移到 v2 后回答仍是旧口径 → 改为从当前已发布版本内容派生摘要。复测：修订 15 天新政策并发布后，客服回答变为新口径且引用 `A-0004 · v2`；同会话旧消息保留 v1 引用（引用带版本可回放的领域设计）。

## 第四轮：客服对话流式输出 + 对话区重做（2026-09-06）

调研 NN/g 客服聊天 UX、Intercom/Zendesk 工作台与 AI 流式输出模式后重做客服对话区：

**流式输出（真实状态机）**：发送 → **thinking**（三点 typing 指示器 + 「正在检索已发布资产…」状态行，约 0.5s TTFT）→ **逐字输出**（每 35ms 揭示 1-3 字，约 60 字/秒，尾部蓝色块状闪烁光标）→ **完成**（光标消失、引用芯片/工具条落位）。流式期间输入锁定、圆形发送按钮**原位换成停止**（Esc 同效）；停止后保留部分文本并标「已中断」，输入立即解锁；刷新中断流自动补全（localStorage 兜底）。引擎在 store 模块层（`startStream`/`STREAM_TICK`/`STREAM_STOP`），持久化只存最终文本。

**对话区对齐真实客服产品**（NN/g + Intercom/Zendesk 惯例）：消息分组（连续同角色隐藏重复头像与时间戳）；时间戳每条消息可见；输入卡式 composer（自增高 textarea、Enter 发送 / Shift+Enter 换行、34px 圆形蓝色发送钮=DSH 发送键、focus 换蓝边）；「结束并回流登记」移到会话头部（Zendesk End Chat 位）；流式期间自动滚动跟随尾部（消息字符数驱动）；typing 指示器带 `role="status"`。

**验证**（页面内探针逐 200ms 采样）：thinking 0→420ms（len=0）→ 627ms 首字 → 1.9s 完成 68 字；1s 处 Esc 中断得 24 字部分文本+已中断标记+按钮复位；刷新后补全渲染（光标消失、引用可见）；回流登记在流式期间禁用。VLM 评审 8.5/10。截图 `verify/v4-*.png`。

复审同时重验：Ops 失败重试与轨迹刷新持久、投放确认/取消、三态筛选、商品页写回来源、390 窄屏（抽屉导航 → 补字段发布 → 客服引用 → 连接层无 publish）。

**环境教训**：长驻 dev 服务器 + 浏览器缓存可能让你对着旧模块测试（症状：改了代码行为不变）。遇到时先 `curl` dev 服务器上的模块源码确认版本，必要时杀端口重启服务器并清浏览器 profile（`playwright-cli delete-data`）。

## 第五轮：闭环补全——让所有消费者对新资产有反应（2026-09-06）

外部审查结论：种子路径上闭环成立，但「自己登记、发布的新资产，下游经常假装没看见」。本轮按清单补全（全部浏览器探针验证，`### Result` 见会话记录）：

**P0（领域正确性）**：
1. **机洗按商品 specSchema 抽字段**：新登记的规格文档（挂商品）机洗时按类目 schema 抽结构化字段（净含量/保质期/材质各有正则，材质通配必须带显式分隔符，否则「未标注材质牌号」会被抽成「牌号」——实测抓到并修掉）；抽不到就弃权，`required` 标记跟 schema 走。**新摄入与种子走同一套闸门**（ADR 0009/0010）。
2. **PUBLISH 在 action 层再校验**：必填缺失或未确认的发布直接拒绝，不依赖按钮禁用。
3. **确认框文案跟类目**：写回预告动态拼 `requiredFields().join('、')`，保温杯显示「净含量、材质」不再出现保质期；README 接待步骤同步改。
4. **总览「已发布」按可检索口径计数**（`publishedV != null`）：修订中的资产线上版仍在服务，不再从计数里消失。

**P1（三个消费者对新资产有反应）**：
1. **客服走真检索**：`retrievePublished`（整段命中权重 3、二元组权重 1、阈值 3，规格文档同分优先，证据句按锚点词抽取）。实测：发布 A-0006 前问口感=拒答转人工；发布后同一问题=「根据已发布的客服对话记录：…」引用 `A-0006 · v1`；问退货=检索命中 `A-0004 · v1` 引用政策原文句。连接层与客服现在是同一份索引、同一个脑子。
2. **微调切最新**：客服「微调」开关切到该类型**最新注册**的底座；导出→注册 M-03 后实测切到 M-03，头部露出「底座：类目微调 · 客服口吻适配 v1（导出 E-001（1 条已发布资产））」。
3. **切片汇入素材中心**：拣选登记同时生成素材任务（标「直播切片汇入」）；运营 Agent 产出引用实时读「已登记且已发布」的素材/切片，轨迹文案动态写引用件数。实测：发布切片资产后运营产出引用 1 件已发布素材。
4. **考核动态抽题**：题库=全部已发布对话资产（开场白从转写首条「顾客：」行提取）。实测 A-0006 发布后「顾客反馈 · 饮用水口感发甜」场景立即出现。
5. **连接层四个工具全部可点**：新增「取资产」（按 资产ID+vN 取快照；待人洗工作版本明确拒绝：外部不可取）与「导出已发布集」（返回 资产ID·vN 清单）演示。

**P2 快赢**：字段行「一键确认」机洗值；版本历史行可点进 `?v=N` 只读视图；元数据补对象键与「被谁用」（会话/导出/考核引用计数）；微调导出芯片带版本号；素材生成文案去掉「渠道用户/发布前」措辞。

**总览 IA**：三张并列闭环卡改为**步进器**（每条闭环一行：名称+一句话+编号节点步进，节点全部是真路由，含 /clips、/models 入口）。

**过程中抓到并修复的两个新 bug**：材质通配正则过抽取（见 P0-1）；Coach 动态题库的选择器返回新数组触发 `useSyncExternalStore` 无限循环崩溃（改为组件外过滤）。

## 第六轮：演示诚实度收尾（2026-09-06）

外部复审定位「剩下是演示诚实度」，四组残留全部闭合（探针逐项验证）：

1. **运营文案跟登记件走**：compose 步产出动态组装——无已发布素材时正文=商品卖点并明说「登记并发布素材后重新运行，正文会跟随」；发布素材后重跑，标题/正文/引用芯片全部取自该素材的已发布版（实测：`投放文案 · 钛钢保温杯 500ml（素材 A-0007 · v1）`，正文为素材开头 80 字，refs=`A-0007 · v1`）。
2. **素材卡状态联动**：登记状态实时读中台资产——发布后卡片显示「已发布 · v1 · 客服检索已可用」，不再永远写「未发布」。
3. **导出冻结版本（ADR 0007）**：导出记录存 `refs: 资产ID+版本`（导出时快照 publishedV），芯片显示冻结版本；A-0004 修订发布到 v2 后，记录仍指 v1，血缘不漂移。注册底座的 source 同步注明「版本已冻结」。
4. **连接层登记可挂商品**：表单加商品下拉；挂上的规格文档机洗同样按类目 schema 抽字段（实测外部登记件抽出 净含量=500ml、材质=316不锈钢）——外部登记不豁免治理闸门。
5. **SET_FIELD/SET_CONTENT 加 store 闸**：只允许作用于 `role=review` 的工作版本，已发布/历史版本不可变（UI 之外也守 ADR 0006）。
6. **已发布口径全链对齐**：列表「已发布」tab 改筛 `publishedV != null`（线上在服务，修订中的资产行内显示「待人洗·修订中 | 线上 vN」徽章），「待人洗」tab 为纯新待办；总览计数同口径，点进列表数字一致。
7. **小项**：总览「注册底座」步进节点跳 /finetune（注册按钮在那里）；考核页头部显示「顾客扮演底座」并与模型配置联动，考核记录回放带当时底座名。

领域结论维持复审判断：原型已足够对齐「中台是核心、未发布不能用、人才能发布、新发布消费者当即可见」；工程刀按 `docs/slices.md` 上脚手架。
